The library creates the beans that run a schema: the `GraphQLSchema`, the `GraphQL` engine and the `GraphQLInvocation`. An application changes what the library builds with customizers, or replaces any of the beans by declaring its own bean of that type. This page lists the customizers first, and then says which application bean wins, and why the three types are not selected the same way.

== Customizers

Three kinds of beans change what the library builds. Several beans of one kind can exist, and they run lowest order first (`@Order` on the bean class or factory method, or `Ordered#getOrder()`).

[cols="3,4,3", options="header"]
|===
|Bean type |Receives |Runs
|`GraphQLTypeDefinitionRegistryCustomizer` |a copy of the `TypeDefinitionRegistry` (the registry bean itself stays unchanged) |before the binding: a type or a field added here is bound like any other
|`GraphQLRuntimeWiringCustomizer` |the `RuntimeWiring.Builder` that holds the library's wiring |after the binding, before the schema is generated
|`GraphQLSchemaCustomizer` |the generated `GraphQLSchema`, and returns the schema to use |last
|===

A `GraphQLRuntimeWiringCustomizer` adds wiring: scalars, directive wirings, field visibility. A replacement of something that the library registered is reported as `[runtime-wiring-override]` (see <<exceptions,Exceptions>>).

To change the generated schema, use a `GraphQLSchemaCustomizer`; the library does not check what it changes. To wrap data fetchers, use a `GraphQLFieldFetcherDecorator` (see <<execution,Execution>>) or a `SchemaDirective` (see <<directives,Directives>>). A `GraphQLSchemaCustomizer` of the example suites handles the `@audit` directive of the schema definition, in the snippet of the <<directives,Directives>> page.

=== Fields a customizer serves

A field that only a hand-written `DataFetcher` serves has no Java member, so the startup would fail with `[field-not-bound]`. The customizer declares the field by claiming it in `getClaimedFields()`, and registers the data fetcher in `customize`. The library does not bind or check a claimed field, and a data fetcher that the customizer registers for it is not a replacement. The compile-time checks do not read `getClaimedFields()`: a claimed field that also has a source resolver method can still fail the build with `[argument-mismatch]`, although the runtime binding succeeds.

* A claim names a field of an object type of the schema, including a field that `extend type` adds. A claim for a type or a field that the schema does not define, or for an interface, fails the startup with `[invalid-claimed-fields]`, which names each coordinate and its customizer. To serve an interface field, claim it on each implementing object type.
* Claiming a field does not make the types it returns reachable. When the claimed field is the only path to a return, input, enum or scalar type, bind that type through another field or list it in `allow.unreachable`, or the startup fails the unreachable-type checks.

== Configuring the `GraphQL` bean

`GraphQLBuilderCustomizer` beans receive the `GraphQL.Builder` of the library's `GraphQL` bean before it is built. The bean uses the selected `GraphQLSchema`: the library's, or an application schema that replaces it, lowest order first. They set a `PreparsedDocumentProvider`, the execution strategies, the default `DataFetcherExceptionHandler` and the like; the <<errors,Errors>> page has an example.

The library installs the `Instrumentation` beans before the customizers run; see <<observability,Observability>>.

== Building the `GraphQL` bean yourself

An application that declares its own `GraphQL` bean keeps the library's `GraphQLSchema` and builds the engine from it (see <<customizationReplace,Replacing the schema or the engine>>). A `GraphQLBuilderCustomizer` configures the builder of the library's bean, so it does not apply to a bean that the application creates.


[[customizationReplace]]
== Replacing the schema or the engine

The library's `GraphQLSchema` and `GraphQL` beans are `@Primary`, and each one is created only when the application has no bean of that type that competes for an unqualified injection point: a bean without a qualifier, or a `@Primary` one. Such a bean wins, and the library does not create its own. A bean with a qualifier, such as `@Named("admin")`, is a secondary bean that is injected by its qualifier. It does not replace the library's bean, so an unqualified `GraphQLSchema` or `GraphQL` injection point still gets the library's.

A request is then served by that schema, and the library's binding does not run for it. At startup the library logs one INFO line for each of the two types, which names the bean that is used and the application's qualified beans that it ignores.

An application that builds its own `GraphQL` keeps the library's `GraphQLSchema`, which is bound at startup. To change the library's `GraphQL` without replacing it, add a api:io.micronaut.graphql.tools.customizer.GraphQLBuilderCustomizer[].

=== Why the library selects these two itself

Micronaut's own modules use `@Secondary` and `@Requires(missingBeans = ...)` for a default bean. The library does not, for `GraphQLSchema` and `GraphQL`, because `missingBeans` counts a qualified bean. With one `@Named("admin")` schema the library's schema would disappear, every unqualified injection point would get the admin schema, and with `@EachProperty` or `@EachBean` beans the first injection would fail with a `NonUniqueBeanException`. The library's selection ignores a qualified bean, which keeps the unqualified injection point on the library's bean. It reads the bean definitions, so it costs well under a millisecond at startup.

`TypeDefinitionRegistry` is different: the library's registry (the one it discovers from the schema files) is `@Secondary` with `@Requires(missingBeans = TypeDefinitionRegistry.class)`, because a registry has no rule for a qualified bean. Any registry bean the application declares replaces it. Micronaut may one day offer a qualifier-aware `missingBeans`; the selection of the schema and the engine can then be replaced by it.

== Replacing the invocation

The library's `GraphQLInvocation` is `@Secondary`, and it declares `@Replaces(DefaultGraphQLInvocation.class)`, so it replaces the transport's default one. An application `GraphQLInvocation` of any kind is what an unqualified injection point gets: a bean without a qualifier, a `@Primary` bean, or a bean that declares `@Replaces(DefaultGraphQLInvocation.class)`. The library's invocation stays registered beside it and is not created unless something asks for it. It steps aside only for a factory method that returns `DefaultGraphQLInvocation` itself and that is `@Primary` or declares `@Replaces(DefaultGraphQLInvocation.class)` without a `factory`, `named` or `qualifier` constraint (a constrained replacement targets another bean and leaves the transport's default in place), because it would replace that bean; an unqualified one does not outrank the transport's default, so the library's invocation stays, and a factory default that another bean replaces is not counted. A `@Primary` factory default that another bean replaces with a `qualifier` constraint (`@Replaces(bean = DefaultGraphQLInvocation.class, qualifier = ...)`) is counted as replaced when it carries that qualifier annotation, and then the library's invocation stays. A template (`@EachProperty` or `@EachBean`) on such a method counts by the beans it expands to, so with no configuration entry the library's invocation stays. Two limits follow from it staying registered, and both fail the startup with a message that names the way out (`ConfigurationException`, checked when `micronaut.graphql.tools.eager-init` is on, which is the default). When every application invocation is `@Secondary`, it ties with the library's one and an unqualified injection point finds two equal candidates: drop `@Secondary` or make it `@Primary` (an application invocation that is not `@Secondary` is enough to avoid the tie). A bean declared with `@EachBean(GraphQLInvocation.class)` is also created for the library's invocation, and a `GraphQL` or `GraphQLSchema` declared that way depends on the invocation that depends on it, so it fails with a circular dependency or, beside an application invocation, with a `NonUniqueBeanException`; the startup reports it before that, and the way out is to target the application's own bean type instead. The startup does not report a template when an application `GraphQL` bean is selected and the template cannot be part of the cycle: a schema template beside an engine that does not inject `GraphQLSchema` or beside an unqualified or `@Primary` application schema, or an engine template beside an engine that is not a template and does not inject an unqualified `GraphQLInvocation` (only direct, unqualified injection points of those beans are read; a container such as `List<GraphQLSchema>`, a qualified dependency that the template expansion also matches, or a replacement that is itself a template are not analysed, and then the startup fails with Micronaut's own circular dependency error instead of the message).

[[customizerOrder]]
== The order of customizers and decorators

Several beans of one customizer type form a chain, and Micronaut's `OrderUtil` sorts it: a bean implements `io.micronaut.core.order.Ordered` or carries `@Order`, and the lower value runs first. A bean with neither has the order `0`, and two beans with the same value keep no defined sequence, so give beans that must run in a fixed sequence different values. A lambda or a closure has no `@Order`, so a lambda bean is ordered by declaring it in a factory method that carries `@Order`.

The chains and what the order means for each:

* `GraphQLSchemaCustomizer`: each one receives the schema that the one before returned. The order is part of the result.
* `GraphQLErrorsCustomizer`: each one receives the list of errors that the one before returned.
* `GraphQLFieldFetcherDecorator`: the lowest value is the outermost wrapper of a field.
* `GraphQLExceptionMapper`: the mappers whose type matches are tried lowest value first, and the first one that answers wins.
* `GraphQLConnectionInterceptor`: lowest value first, until one rejects the connection.

[[experimentalTypes]]
== Types that are marked `@Experimental`

`io.micronaut.core.annotation.Experimental` marks an API that can still change within the 1.0 line. The <<publicApi,Public API>> page marks it. One type of the library carries it: `DataLoaderBatchStatistics`. A change to it is listed on the page of breaking changes like any other. `GraphQLContextContributor`, `GraphQLFieldFetcherDecorator`, `GraphQLConnectionInterceptor` and `GraphQLTransport` are stable since 1.0.0-M5, and the breaking-change policy covers them.
