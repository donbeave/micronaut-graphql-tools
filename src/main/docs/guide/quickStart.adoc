This page binds a small schema to a resolver. The class examples are shown in Java, Kotlin and Groovy; pick a tab. The repository declarations of step 1 and the `curl` command of step 5 are plain source blocks, the same for every language.

The library is for Micronaut 4. Micronaut Launch offers Micronaut 5 by default, so choose a Micronaut 4 version there. A Launch application that is already on Micronaut 5 has to be changed by hand: set the Micronaut Gradle plugins (`io.micronaut.application` and `io.micronaut.aot`) to a 4.x version, `micronautVersion` in `gradle.properties` to a 4.10 platform version, and `distributionUrl` in `gradle/wrapper/gradle-wrapper.properties` to a Gradle version that the 4.x plugin supports. The first query of this page ran on an empty application set up this way: plugins 4.6.2, `micronautVersion=4.10.25` and Gradle 8.14.3.

1. Add the dependency. The macro renders the Gradle and Maven declarations:
+
dependency:micronaut-graphql-tools[groupId=io.micronaut.graphql.tools,version=1.0.0-M4]
+
Milestone previews are published to the https://github.com/donbeave/micronaut-graphql-tools/packages[GitHub Packages] Maven registry of the repository, not to Maven Central, so the build also needs that repository. GitHub Packages needs a token with the `read:packages` scope even to download a public package (see <<compatibility,Compatibility>>). In Gradle:
+
[source,groovy]
----
repositories {
    mavenCentral()
    maven {
        url = uri("https://maven.pkg.github.com/donbeave/micronaut-graphql-tools")
        credentials {
            username = providers.gradleProperty("gpr.user").orNull ?: System.getenv("GITHUB_ACTOR")
            password = providers.gradleProperty("gpr.key").orNull ?: System.getenv("GITHUB_TOKEN")
        }
        content { includeGroup("io.micronaut.graphql.tools") }
    }
}
----
+
In Maven, add the repository with the id `graphql-tools`; the `<server>` entry with the same id carries your user name and token in `~/.m2/settings.xml`:
+
[source,xml]
----
<repositories>
  <repository>
    <id>graphql-tools</id>
    <url>https://maven.pkg.github.com/donbeave/micronaut-graphql-tools</url>
  </repository>
</repositories>
----
+
To use a build of your own checkout instead, run `./gradlew publishToMavenLocal` in the repository and add `mavenLocal()` (Gradle) to the repositories; Maven reads its local repository without a declaration (see `CONTRIBUTING.md`). That publishes to your machine only.
+
The BOM (`micronaut-graphql-tools-bom`) sets the version of every module of the library, so the other module snippets of this guide name no version. Import it in Gradle with `implementation(platform("io.micronaut.graphql.tools:micronaut-graphql-tools-bom:1.0.0-M4"))`, or in the `dependencyManagement` of a Maven build with `<type>pom</type>` and `<scope>import</scope>`. The library does not bring a JSON codec (BC-26). Add the one your application uses, for example `micronaut-jackson-databind` or `micronaut-serde-jackson`, to the same `dependencies` block.
+
The HTTP and WebSocket transport is the `io.micronaut.graphql:micronaut-graphql` module. `micronaut-graphql-tools` declares it as an API dependency, so it is already on the classpath, and the Micronaut platform BOM manages its version. To name it in your build, add `implementation("io.micronaut.graphql:micronaut-graphql")` (Gradle) or the same coordinates with no `<version>` (Maven). The endpoint also needs an HTTP server, for example the `netty` runtime that an application from Micronaut Launch has.

2. Define the GraphQL schema in `.graphqls` files in the `src/main/resources/graphql` folder. The library finds them at startup (see the Schema page), and a `schema { }` block is optional:
+
[source,graphql]
----
type Query {
  allBooks: [Book!]!
}

type Book {
  id: ID!
  title: String!
}
----

== Annotations

The library provides these annotations (package `io.micronaut.graphql.tools.annotation`):

* `@GraphQLRootResolver` defines a root-level resolver, a GraphQL entry point such as a query or mutation. Like @api:io.micronaut.graphql.tools.annotation.GraphQLTypeResolver[], it makes no bean: the class needs `@Singleton` or another scope annotation.
* @api:io.micronaut.graphql.tools.annotation.GraphQLType[] maps a Java class to a GraphQL type.
* `@GraphQLTypeResolver` specifies a resolver for a field of a specific GraphQL type, to map nested or complex fields.
* @api:io.micronaut.graphql.tools.annotation.GraphQLInput[] defines a GraphQL input type, structured input data for mutations or queries.
* @api:io.micronaut.graphql.tools.annotation.GraphQLField[] marks a method of a `@GraphQLType` class as a field resolver, so that methods with arguments (or a `DataFetchingEnvironment` parameter) can back a GraphQL field. `@GraphQLField("name")` on a method or a property binds the field of that name (see <<renaming,Binding a field to a differently named member>>).
* `@GraphQLSchemaCoordinate("Type.field")` names the field a resolver method binds; it is meant for resolver contracts (interfaces).

The marker interfaces api:io.micronaut.graphql.tools.resolver.QueryResolver[], api:io.micronaut.graphql.tools.resolver.MutationResolver[], api:io.micronaut.graphql.tools.resolver.SubscriptionResolver[] and `TypeResolver<T>` (package `io.micronaut.graphql.tools.resolver`) declare resolver contracts without an annotation; see <<resolverContracts,Resolver Contracts>>.

GraphQL enums map to Java enums annotated with `@Introspected`, and unions and interfaces to Java interfaces, without an annotation of their own.
