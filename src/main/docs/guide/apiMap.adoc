This page tells you which package holds what, which packages you may import from, and which ones are implementation. Every Java package of the library modules has a `package-info.java` that says the same thing in the Javadoc, and the build checks that each of them exists.

== The rules

* A package has one responsibility. A package with more than 15 types is a smell: the build lists the ones that are over the limit, each with a reason, and a package that is no longer over the limit leaves the list.
* The public API is what you import from application code: the annotations, the customizer, mapping and directive interfaces and mapping contexts, `CustomWiring`, the configuration class, `ArgumentValue`, `BindingManifest`, `BindingCode` and the one exception, `SchemaBindingException`. The table below lists where each one is. Everything else is implementation and can change in any release.
* Implementation is marked in two ways. A type is annotated `@Internal` (`io.micronaut.core.annotation.Internal`, the same marker Micronaut uses), and a package of implementation types carries the `internal` segment in its name and an `@Internal` on the package in its `package-info.java`. Micronaut itself follows this convention.
* A public type never lives in an `internal` package, and an internal type belongs in an `internal` package. The code follows both halves; see <<plannedLayout,Planned layout>> for what is still to be split.
* If a package holds both, the Javadoc of its `package-info.java` says so, and an `@Internal` type is not API even when it is `public`.

== Which package do I import from?

[cols="4,5", options="header"]
|===
|I want to |Import from
|Mark a resolver class, a method, a parameter or an input class |`io.micronaut.graphql.tools.annotation`
|Catch a startup failure |`io.micronaut.graphql.tools.exceptions` (`SchemaBindingException`; match on its code)
|Read an error code |`io.micronaut.graphql.tools.binding` (`BindingCode`)
|Change a setting in code |`io.micronaut.graphql.tools.config` (`GraphQLToolsConfiguration`)
|Change the `GraphQL` builder, the schema, the runtime wiring or the type registry |`io.micronaut.graphql.tools.customizer` (the `*Customizer` interfaces)
|Map a custom scalar, or a union member to a Java type |`io.micronaut.graphql.tools.mapping` (`GraphQLScalarMapping`, `SchemaMappingDictionary`)
|Tell an omitted argument from an explicit `null` |`io.micronaut.graphql.tools.input` (`ArgumentValue`)
|Wire a directive |`io.micronaut.graphql.tools.directive` (`SchemaDirective`)
|Read what the schema is bound to |`io.micronaut.graphql.tools.manifest` (`BindingManifest`)
|===

Do not import any type annotated `@Internal`, and nothing from a package named `internal`.

This is the layout of the code now. `graphql-tools` is the library, `graphql-tools-binding` the shared binding rules, `graphql-tools-processor` the compile-time checks and `graphql-tools-tck` the execution-behaviour TCK of this repository. In the audience column, `Mixed` means the package holds public API and `@Internal` types, and `Internal` means every type is implementation.

== Planned layout

The public API is split into its role packages (`config`, `customizer`, `mapping`, `directive`, `input` and `manifest`), and the root package `io.micronaut.graphql.tools` holds no types. What is still to do is on the implementation side: the `internal` package still holds the factories, the eager binding and the shared helpers, and `internal.exceptions` holds the failure classes, one for each kind. The packages of `graphql-tools-binding` already follow the convention and stay; whether `BindingCode` stays public is decided with the exception shrink. In `graphql-tools-processor`, `processing` is deleted when the visitor replaces the JSR-269 processor, and `visitor` stays. Each change that moves a public type gets an entry in <<breaks,Breaking Changes>> and in the migration page.

== How the build keeps this true

`PackageDocumentationSpec` fails when a Java package of the four modules has no `package-info.java`, when a `package-info.java` has no description, when a package has more than 15 types without a listed exception, when the package list of this page differs from the packages of the code, or when `@Internal` on a package and the audience column of this page disagree.
