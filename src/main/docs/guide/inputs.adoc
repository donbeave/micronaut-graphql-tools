The values of arguments and input objects reach a resolver in the Java type the method declares. The library builds one converter for each argument and each input field at startup, from the declared type and the GraphQL type, and a request only runs it. The conversion uses the bean introspection that Micronaut generates at compile time. It uses no reflection and no Jackson, so it behaves the same on the JVM and in a native image.

== Binding by name

A resolver parameter is bound to the field argument with the same name, whatever its position. The source object of a type resolver method stays the first parameter; a parameter of an injected kind (the `DataFetchingEnvironment`, the context, a `DataLoader` and the others of <<resolverParameters,Resolver Parameters>>) takes any position after it; every other parameter is matched by name. The plan from names to positions is built once at startup, so a request does no name lookup.

snippet::example.tck.ArgumentsScenario[project-base="test-suite", source="test", tags="by-name", indent="0"]

`@GraphQLArgument("<name>")` binds a parameter whose name cannot be the argument's, such as the argument `in`, which no Java, Kotlin or Groovy parameter can be named. The annotation on a parameter of an interface or superclass method also applies to the method that overrides it. Reordering the arguments of the schema field does not change which parameter gets which value.

The startup and the compile-time check (the visitor of `graphql-tools-processor`) apply the same rule and report the same code, `argument-mismatch`, with the same schema coordinate, for a parameter that names no argument (the message lists the arguments of the field), for two parameters that name one argument, and for a number of parameters that differs from the number of arguments. A parameter that is not the source object or an injected parameter (see <<resolverParameters,Resolver Parameters>>) and has a name the field does not have is never matched by position: there is no positional opt-out.

=== Where the names come from

[cols="2,3", options="header"]
|===
| Parameter of | Name
| A method declared in a class of the module that Micronaut processes (Java, Kotlin or Groovy) | The name in the source. The compiler needs no `-parameters`: Micronaut records the name when it processes the class.
| A method inherited from a class file, such as a superclass or an interface of a dependency | The name that the class file carries. javac writes it with `-parameters` or, for a method that has a body, as local variable debug information with `-g`, which the Gradle and Maven compile tasks pass by default. An abstract or interface method has no body to hold that information, so its names need `-parameters`. A class file built without the needed flag has no names: the name is `arg0`.
|===

A parameter without a name fails like any other parameter with no argument of that name, and the message says what to do: compile the class that declares the method with `-parameters`, or bind the parameter with @api:io.micronaut.graphql.tools.annotation.GraphQLArgument[]. Startup and compile time see the same name for the same class file.

== What the converters do

graphql-java coerces every value first: scalar values, enum constants, a `Map` per input object and a `List` per list. The converter of each declared type then does the least that is needed:

[cols="2,3", options="header"]
|===
| Declared type | Conversion
| `String`, `Boolean`, `Integer`, `Long`, `Short`, `BigDecimal`, `BigInteger`, `Double` (also `int`, `long` and the other primitives) | None: the value is the declared type already, and an unboxed parameter takes it as it is.
| `float`, `Float` | Narrowed from the `Double` that graphql-java coerces for a Float.
| A Java enum | None: the values provider of the enum makes graphql-java coerce the enum value to the Java constant.
| `List`, `Collection`, `Iterable` | A new mutable `ArrayList`; the element converter runs on each element.
| `Set`, `SortedSet`, `Deque`, `Queue` | A new `LinkedHashSet` (the order of the list is kept), `TreeSet` or `LinkedList`.
| An input class | A new instance, built from the class's introspection.
| The class of a custom scalar | None when the scalar parsed an instance of it; otherwise the Micronaut `ConversionService`.
|===

Any other declared collection fails the startup with `[unsupported-input-type]`.

== Input classes

An input class is a class annotated with @api:io.micronaut.graphql.tools.annotation.GraphQLInput[], which is `@Introspected`. The library instantiates it through the introspected constructor, which takes the input fields that match its parameters. Every other input field is then set through its property. A record, a Kotlin data class and an immutable class need nothing but the annotation:

snippet::example.tck.ArgumentsScenario[project-base="test-suite", source="test", tags="constructor-input", indent="0"]

The rules:

* A field that the client leaves out is not set, so the class keeps the value it gives itself. An explicit `null` is set as `null`; for a primitive property the default stays.
* A constructor parameter that no input field provides gets `null`, or the default of a primitive. A Kotlin default argument applies to an omitted field, and to an explicit `null` only for a parameter with a non-null type: see <<languageSupport,Language Support>>.
* Every input field needs a property of the same name. The startup fails with `[field-not-bound]` for a missing one, and with `[input-field-not-settable]` for a read-only property that no constructor parameter of the same name takes.
* A property is settable when it has a setter or a constructor parameter, as the introspection lists them. The same definition decides `[input-field-not-settable]`, the unmapped properties at startup and the compile-time check.
* In strict mode, a settable property that no input type defines fails the startup (`[unmapped-input-property]`), naming the class and the property. A class that several input types map to, such as one DTO for a create and a rename input, is checked once: a property is unmapped only when none of those types has a field for it, so each type may cover a different subset.
* To exclude a property that the server populates, annotate it with @api:io.micronaut.graphql.tools.annotation.GraphQLIgnore[]. The property is then not reported, and the binding manifest lists it as `~ignored`. A field that names the property still binds it. Jackson annotations such as `@JsonIgnore` are not read.
* The compile-time check cannot see the resolvers of other classes. It reports a property only when no input type of the schema that it did not reach could cover it, so it never reports a property that the startup accepts.

== Conversion errors

A value that cannot be converted (see <<errors,Errors>>) is a GraphQL error with `extensions.code` `INPUT_CONVERSION_FAILED` that names the argument as `Type.field(argument)` and the path inside the value. The resolver is not called, the field is `null` and the other fields run.

== Customization

Customization goes through Micronaut `TypeConverter` beans and the scalar mapping, not through a mapper:

* A `TypeConverter<Map, SomeInput>` bean builds the instances of `SomeInput` itself, api:io.micronaut.graphql.tools.input.ArgumentValue[] properties included: the library does not touch the result. The class keeps its introspection, because the startup checks read it.
* A api:io.micronaut.graphql.tools.mapping.GraphQLScalarMapping[] declares which Java classes a custom scalar produces. A value that is not an instance of the declared class goes through the Micronaut `ConversionService`, which holds the application's `TypeConverter` beans.

== ArgumentValue

An `ArgumentValue<T>` argument or input field tells an omitted value from an explicit `null`. It needs a nullable GraphQL type; declaring it is all it takes, there is no option. A type without an `ArgumentValue` gets no omission handling at all. A `List<ArgumentValue<T>>` is rejected at startup with `[unsupported-input-type]`, because a single list element cannot be omitted. The converter sets it from the keys of the coerced `Map`, while it builds the instance: no getter is called, and no second pass walks the converted object. Besides `isOmitted()`, `isNull()`, `isPresent()` and `getRequired()`, two methods read the value without a branch:

* `asOptional()` returns an `Optional` that is empty for an omitted value and for an explicit `null`.
* `ifPresent(Consumer)` runs the consumer only for a provided, non-null value.

A constructor parameter of that type works too, so a record or a Kotlin data class can hold an `ArgumentValue` without a setter. The constructor receives `ArgumentValue.omitted()` when the client leaves the field out and the schema declares no default, and `ArgumentValue.ofNullable(value)` otherwise, including the schema default.
