Strict mode is a set of ten checks that fail the startup on a binding that works but is probably a mistake. Each check has a code. The code is the key under `micronaut.graphql.tools.checks`, the word in an `allow.findings` line, the token at the start of the startup error and the word after `!` in a line of the <<manifest,binding manifest>>. The settings themselves are in the <<checkSeverity,configuration reference>>; this page says what each check finds and how to fix it.

== Severity

Each check has one of three severities, set with `micronaut.graphql.tools.checks.<code>`:

[cols="1,4", options="header"]
|===
|Severity |What the check does with a finding
|`fail` (the default of every check) |Fails the startup. All findings of the check are reported together.
|`warn` |Logs one warning per check that lists the findings, and goes on. The findings are in the manifest.
|`ignore` |Skips the check: it does no work and writes no manifest line.
|===

[configuration]
----
micronaut:
  graphql:
    tools:
      checks:
        unreachable-value-type: warn
        unused-dictionary-entry: ignore
----

`strict` is the shorthand for the checks that have no entry: `true` (the default) leaves them at `fail`, and `false` makes them `warn`. An explicit `checks.<code>` entry wins over `strict`. See the <<checkSeverity,configuration reference>>.

The severity settings apply to the startup only. The compile-time checks never read `strict`, `checks.<code>` or `allow.*`; a finding that they report is suppressed by an annotation only (see <<strictModeEscape,Accept a finding>>). `precedence` is not a check and `strict` does not relax it.

=== Two settings are called strict

`micronaut.graphql.tools.strict` is the shorthand above. It is unrelated to the strict mode of graphql-java's `RuntimeWiring` builder, which fails with graphql-java's own exception and which `strict: false` does not relax (see <<exceptions,the error reference>>).

== The checks

[cols="3,4,4", options="header"]
|===
|Code |What it finds |The fix
|`unbound-resolver-method` (compile time) |A method of a resolver bean that binds no field. Which methods count is in <<compileTime,Compile-Time Verification>>. |Remove the method, make it bind a field, or put `@GraphQLIgnore` on it.
|`root-method-several-operations` (compile time) |A root resolver method that binds the field of its name on more than one operation type. |Give each operation type its own method with `@GraphQLSchemaCoordinate`.
|`unbound-enum-constant` (compile time) |A Java enum constant that has no value in the schema enum. |Add the value to the schema, remove the constant, or put `@GraphQLIgnore` on it.
|`unmapped-input-property` (compile time) |A settable property of an input class that the GraphQL input type does not define. |Add the field to the input type, remove the property, or put `@GraphQLIgnore` on it.
|`nullable-primitive` (compile time) |A primitive argument or input property for a nullable built-in scalar: a `null` cannot reach it. |Use the wrapper class, or make the GraphQL type non-null.
|`unreachable-type` |An object, interface or union type that the binding does not reach. |Bind it through a field, remove it from the schema, or list it in `allow.unreachable`.
|`unreachable-value-type` |An enum, input or scalar type that nothing uses. |The same.
|`unused-dictionary-entry` |A `SchemaMappingDictionary` entry for a type that the schema does not bind. |Remove the entry or bind the type.
|`interface-read-through-implementation` |An object type mapped to a Java interface that is read through the introspection of its implementation. |Annotate the interface with `@GraphQLType` or `@Introspected`, and declare the getter on it.
|`unwired-directive` |A directive that the schema applies and nothing wires. |Wire it: directive wiring is what enforces an authorization directive, so keep this check at `fail` for one. A directive on the schema definition or on a directive-definition argument is not reached by a `SchemaDirectiveWiring`; see the directive section of the <<checkSeverity,configuration reference>> for `allow.schema-customizer-directives` and `allow.inert-directives`, and use them only as it describes.
|===

The definitions, such as which methods, types and properties count, are in <<compileTime,Compile-Time Verification>> and the <<checkSeverity,configuration reference>>. The error that each check throws, and the order in which they run, are in the <<exceptions,error reference>>.

== Accept a finding

A member that binds no field on purpose does not need to relax a check for the whole application:

* `@GraphQLIgnore` on a member that binds no field on purpose. The member is not reported, and the manifest records it, so a review sees what was set aside.
* `allow.findings` lists one finding by its manifest line, exactly as the manifest writes it. An entry that no longer matches a finding fails the startup, so the list cannot go stale. Use it, and the `allow.*` lists below, only for findings that carry no access decision, never for an authorization directive.
* `allow.unreachable`, `allow.inert-directives` and `allow.schema-customizer-directives` accept a type or a directive; see the <<checkSeverity,configuration reference>>.

[configuration]
----
micronaut:
  graphql:
    tools:
      allow:
        findings:
          - "!unbound-resolver-method example.BookQuery#helper(java.lang.String)"
----

== The removed keys

A configuration key that was removed fails the startup with `[removed-configuration-key]`, and the message names the replacement. The removed keys and their replacements are listed in the <<migration,migration page>> (BC-27 and BC-28).
