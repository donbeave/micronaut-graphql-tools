This page is the error reference. Every startup failure, every strict check and every compile-time diagnostic has one code. The same code is the token in square brackets at the start of the message (`[unbound-enum-constant] ...`, at startup and at compile time), the value of `SchemaBindingException#getCode()`, the word after `!` in a binding manifest line (`!unbound-enum-constant example.Color#BLUE`), and the name of the check in `checks.<code>` and `allow.findings`. The codes are lower-case kebab-case words. They are the values of the api:io.micronaut.graphql.tools.binding.BindingCode[] enum of `graphql-tools-binding`, the one public type of that module: a code never changes after a release, and a new failure adds a new code.

== The exception

Every failure of the binding at startup is a api:io.micronaut.graphql.tools.exceptions.SchemaBindingException[], which extends Micronaut's `io.micronaut.context.exceptions.ConfigurationException`. So `catch (ConfigurationException)` catches every binding failure, and Micronaut's startup error reporting treats it like its own configuration errors. The scalars module throws `ConfigurationException` directly for an invalid `micronaut.graphql.tools.scalars.*` value, the same base without a code, and so does a `resolver-directives` entry that the schema does not declare. `SchemaBindingException` is the one public exception of the library: catch it, or `ConfigurationException`, and match on `getCode()` (the `code` property in Groovy and Kotlin), which returns the `BindingCode` of the failure. With eager initialization Micronaut wraps the failure in a `BeanInstantiationException`, so look through the causes. The classes that build each failure are internal (`io.micronaut.graphql.tools.internal.exceptions`): do not catch or import them.

* `getCoordinate()` is the schema coordinate of the element that the failure is about (`Query.book`, `Book.isbn`, `Filter.name`), or `null` for a failure that is about no single element. `getMappingContext()` says more about it: the Java class and method, the argument, the source location.
* `getMessage()` starts with `[code]` and names the coordinate, the Java element and the way out.
* An aggregate has a code of its own and carries its findings. `binding-failures` lists the failures of several fields in `getFailures()`, sorted by coordinate, and each of them has its own code and coordinate; the first one is the cause and the others are suppressed exceptions. When the failures come from different checks (the unreachable types, the @api:io.micronaut.graphql.tools.annotation.GraphQLSchemaCoordinate[] bindings and the strict findings), `getFailures()` keeps the order of those checks instead, and a failure that is about several elements has a `null` coordinate: test `getCoordinate()` for `null` and match on `getCode()`. `strict-findings` lists the strict findings: `getCodes()` returns the check code of each one, and each line of the message starts with it.

[source,java]
----
try (ApplicationContext context = ApplicationContext.run()) {
    context.getBean(GraphQLSchema.class);
} catch (RuntimeException e) {
    // with eager-init (the default) the failure aborts the start; Micronaut wraps it, so look through the causes
    for (Throwable cause = e; cause != null; cause = cause.getCause()) {
        if (cause instanceof SchemaBindingException failure && failure.getCode() == BindingCode.FIELD_NOT_BOUND) {
            log.error("{} is not bound", failure.getCoordinate());
        }
    }
}
----

== Checks

A check is a strict-mode finding. In the compile-time column, `yes` means the compile-time check reports it too, with the same code and coordinate; the other checks need the whole program and run at startup only.

A conditional bean (`@Requires`, `@Replaces`) gets the same per-class compile-time checks as any other bean, because the compile-time check does not know the environment. The message of `precedence-ambiguity` names the field coordinate, both members, and the ways out: a resolver directive, `@GraphQLSchemaCoordinate`, @api:io.micronaut.graphql.tools.annotation.GraphQLIgnore[] or the `precedence` setting.

The codes that run at compile time and have no startup form (`processor-option-unknown`, `processor-option-invalid`, `processor-option-removed`, `processor-schema-not-configured`, `processor-schema-not-found`, `processor-internal-error`) are errors of the compile-time check itself. `schema-invalid` is a compile-time code: the compile-time check reports a schema that cannot be parsed or merged. The startup emits it for a schema file that the discovery cannot parse or merge; a schema that graphql-java rejects later still fails with graphql-java's own `SchemaProblem`. `schema-definition-not-provided` is reported by both: a schema with no `schema` block and no object type named `Query` fails the compile-time check and the startup with the same code and no coordinate. `schema-not-found` is a startup code: no file at `micronaut.graphql.tools.schema.locations`, a missing literal file, or an invalid location.

`nullable-primitive` and `coordinate-on-non-resolver` are emitted at startup and at compile time with the same code. A primitive Java type for an argument or input field of a nullable built-in scalar fails the startup with `nullable-primitive` (not `incorrect-class-mapping`); a primitive for a nullable custom scalar keeps `incorrect-class-mapping`, because the compile-time check cannot see the scalar mapping. A `@GraphQLSchemaCoordinate` on a bean that is neither a @api:io.micronaut.graphql.tools.annotation.GraphQLRootResolver[] nor a @api:io.micronaut.graphql.tools.annotation.GraphQLTypeResolver[] fails the startup with `coordinate-on-non-resolver` (not `unknown-schema-coordinate`); the other invalid coordinates keep `unknown-schema-coordinate`, and a startup with both kinds reports both under `binding-failures`.

`checks.<code>` and the `[code]` of a configuration failure use the same codes: `invalid-check-setting` (an unknown check or severity), `removed-configuration-key` (a key that was removed in 1.0.0-M3, BC-27, with its replacement) and `invalid-allow-findings` (an `allow.findings` entry that is not a manifest line of a check, or that matches no finding). They fail the startup like any other code.

`class-not-introspected` for the Java class of an input type or an enum has the schema type as its coordinate (`Filter`, `Color`), not the argument or field that reaches it, so that it is the same whichever use the startup binds the type from.

The compile-time check reports the findings of the inputs and enums that a resolver class reaches through its parameters (and, for an enum, its return type) in the order of the startup: it stops where the startup stops, and it reports the strict checks (`unbound-enum-constant`, `unmapped-input-property`, `unbound-resolver-method`, `root-method-several-operations`) only for a class with no binding failure, because the startup runs them after a binding that failed nowhere. A class is introspected for the compile-time check when it carries `@Introspected` or an annotation that carries it (@api:io.micronaut.graphql.tools.annotation.GraphQLInput[], @api:io.micronaut.graphql.tools.annotation.GraphQLType[], `@Serdeable`); a class that a @api:io.micronaut.graphql.tools.annotation.GraphQLModels[] of the same compilation lists (see <<models,Model Classes>>) is seen as introspected too, wherever that annotation is declared, but a class that is introspected through `@Introspected(classes = ...)` or `(packages = ...)` on another class, or by a dependency, cannot be seen from one class. So `class-not-introspected` is the one finding that the compile-time check reports as a warning and never as an error: a compile error must also be a startup failure, and this class passes at startup. The startup decides. The warning goes away when the class carries `@Introspected` itself or a `@GraphQLModels` of the same compilation lists it; the compile-time check has no other switch for it, short of `micronaut.graphql.tools.processor.checks=false`. A build that turns compiler warnings into errors (`-Werror`) fails on this warning too, also for a class that is introspected elsewhere and binds at startup: annotate the class itself, list it in `@GraphQLModels`, or switch the checks off.
