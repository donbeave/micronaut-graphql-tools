This page is the error reference. Every startup failure, every strict check and every compile-time diagnostic has one code. The same code is the token in square brackets at the start of the message (`[unbound-enum-constant] ...`, at startup and at compile time), the value of `SchemaBindingException#code()`, the word after `!` in a binding manifest line (`!unbound-enum-constant example.Color#BLUE`), and the name of the check in `checks.<code>` and `allow.findings`. The codes are lower-case kebab-case words. They are the values of the `BindingCode` enum of `graphql-tools-binding`, the one public type of that module: a code never changes after a release, and a new failure adds a new code.

== The exception

Every startup failure is a `SchemaBindingException` (`MethodNotFoundException`, `MultipleMethodsFoundException`, `IncorrectClassMappingException`, `UnreachableTypesException`, `StrictModeException`, `BindingFailuresException`, `InvalidConfigurationException`, and the others in the `exceptions` package). `code()` returns its code. An aggregate has a code of its own and carries its findings: `BindingFailuresException` (`binding-failures`) lists the failures of several fields, and each of them has its own code; `StrictModeException` (`strict-findings`) lists the strict findings, `getCodes()` returns the check code of each one, and each line of the message starts with it. Issue #109 collapses the subclasses into internal classes behind one public exception; the codes stay.

== Checks

A check is a strict-mode finding. In the compile-time column, `yes` means the compile-time check reports it too, with the same code and coordinate; the other checks need the whole program and run at startup only.

[cols="3,1,1,6", options="header"]
|===
|Code |Kind |Compile time |Meaning
|`unbound-resolver-method` |check |yes |A resolver method binds no schema field.
|`root-method-several-operations` |check |yes |A root resolver method binds fields of several operation types.
|`unbound-enum-constant` |check |yes |A Java enum constant has no value in the schema enum.
|`unmapped-input-property` |check |yes |A settable property of an input class has no field in the GraphQL input type.
|`nullable-primitive` |check |yes |A primitive parameter or input property sits at a nullable schema position.
|`unreachable-type` |check |no |The schema defines an object, interface or union type that no root field reaches.
|`unreachable-value-type` |check |no |The schema defines an enum, input or scalar type that no root field reaches.
|`unused-dictionary-entry` |check |no |A SchemaMappingDictionary entry names a type that the schema does not bind.
|`interface-read-through-implementation` |check |no |An interface type is read through one of its implementations.
|`unwired-directive` |check |no |The schema applies a directive that has no wiring.
|===

The codes that run at compile time and have no startup form (`processor-option-unknown`, `processor-option-invalid`, `processor-option-removed`, `processor-schema-not-configured`, `processor-schema-not-found`, `processor-internal-error`) are errors of the compile-time check itself. `schema-invalid` is a compile-time code: the compile-time check reports a schema that cannot be parsed or merged. The startup emits it as `SchemaDiscoveryException` for a schema file that the discovery cannot parse or merge; a schema that graphql-java rejects later still fails with graphql-java's own `SchemaProblem`. `schema-not-found` is a startup code: no file at `micronaut.graphql.tools.schema.locations`, a missing literal file, or an invalid location.

`coordinate-on-non-resolver` is registered for the compile-time check and is not emitted at startup. `nullable-primitive` is emitted at startup for a primitive at a nullable built-in scalar; for a custom scalar the failure keeps the code `incorrect-class-mapping`.

`checks.<code>` and the `[code]` of a configuration failure use the same codes: `invalid-check-setting` (an unknown check or severity), `removed-configuration-key` (a key that was removed in 1.0.0-M3, BC-26, with its replacement) and `invalid-allow-findings` (an `allow.findings` entry that is not a manifest line of a check, or that matches no finding). They are raised as `InvalidConfigurationException`.
