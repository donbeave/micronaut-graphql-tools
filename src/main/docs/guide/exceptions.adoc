This page is the error reference. Every startup failure, every strict check and every compile-time diagnostic has one code. The same code is the token in square brackets at the start of the message (`[unbound-enum-constant] ...`, at startup and at compile time), the value of `SchemaBindingException#code()`, the word after `!` in a binding manifest line (`!unbound-enum-constant example.Color#BLUE`), and the name of the check in `checks.<code>` and `allow.findings`. The codes are lower-case kebab-case words. They are the values of the `BindingCode` enum of `graphql-tools-binding`, the one public type of that module: a code never changes after a release, and a new failure adds a new code.

== The exception

Every startup failure is a `SchemaBindingException` (`MethodNotFoundException`, `MultipleMethodsFoundException`, `IncorrectClassMappingException`, `UnreachableTypesException`, `StrictModeException`, `BindingFailuresException`, and the others in the `exceptions` package). `code()` returns its code. An aggregate has a code of its own and carries its findings: `BindingFailuresException` (`binding-failures`) lists the failures of several fields, and each of them has its own code; `StrictModeException` (`strict-findings`) lists the strict findings, `getCodes()` returns the check code of each one, and each line of the message starts with it. Issue #109 collapses the subclasses into internal classes behind one public exception; the codes stay.

== Checks

A check is a strict-mode finding. In the compile-time column, `yes` means the compile-time check reports it too, with the same code and coordinate; the other checks need the whole program and run at startup only.

[cols="3,1,1,6", options="header"]
|===
|Code |Kind |Compile time |Meaning
|`unbound-resolver-method` |check |yes |A resolver method binds no schema field.
|`root-method-several-operations` |check |yes |A root resolver method binds fields of several operation types.
|`unbound-enum-constant` |check |yes |A Java enum constant has no value in the schema enum.
|`unmapped-input-property` |check |yes |A settable property of an input class has no field in the GraphQL input type.
|`nullable-primitive` |check |yes |A primitive parameter or input property sits at a nullable schema position.
|`unreachable-type` |check |no |The schema defines an object, interface or union type that no root field reaches.
|`unreachable-value-type` |check |no |The schema defines an enum, input or scalar type that no root field reaches.
|`unused-dictionary-entry` |check |no |A SchemaMappingDictionary entry names a type that the schema does not bind.
|`interface-read-through-implementation` |check |no |An interface type is read through one of its implementations.
|`unwired-directive` |check |no |The schema applies a directive that has no wiring.
|===

The codes that run at compile time and have no startup form (`processor-option-unknown`, `processor-option-invalid`, `processor-option-removed`, `processor-schema-not-configured`, `processor-schema-not-found`, `processor-internal-error`) are errors of the compile-time check itself. `schema-invalid` is a compile-time code: the compile-time check reports a schema that cannot be parsed or merged. The startup emits it as `SchemaDiscoveryException` for a schema file that the discovery cannot parse or merge; a schema that graphql-java rejects later still fails with graphql-java's own `SchemaProblem`. `schema-not-found` is a startup code: no file at `micronaut.graphql.tools.schema.locations`, a missing literal file, or an invalid location.

`nullable-primitive` and `coordinate-on-non-resolver` are emitted at startup and at compile time with the same code. A primitive Java type for an argument or input field of a nullable built-in scalar fails the startup with `nullable-primitive` (not `incorrect-class-mapping`); a primitive for a nullable custom scalar keeps `incorrect-class-mapping`, because the compile-time check cannot see the scalar mapping. A `@GraphQLSchemaCoordinate` on a bean that is neither a `@GraphQLRootResolver` nor a `@GraphQLTypeResolver` fails the startup with `coordinate-on-non-resolver` (not `unknown-schema-coordinate`); the other invalid coordinates keep `unknown-schema-coordinate`, and a startup with both kinds reports both in a `BindingFailuresException`.

`class-not-introspected` for the Java class of an input type or an enum has the schema type as its coordinate (`Filter`, `Color`), not the argument or field that reaches it, so that it is the same whichever use the startup binds the type from.

The compile-time check reports the findings of the inputs and enums that a resolver class reaches through its parameters (and, for an enum, its return type) in the order of the startup: it stops where the startup stops, and it reports the strict checks (`unbound-enum-constant`, `unmapped-input-property`, `unbound-resolver-method`, `root-method-several-operations`) only for a class with no binding failure, because the startup runs them after a binding that failed nowhere. A class is introspected for the compile-time check when it carries `@Introspected` or an annotation that carries it (`@GraphQLInput`, `@GraphQLType`, `@Serdeable`); a class that is introspected through `@Introspected(classes = ...)` or `(packages = ...)` on another class, or by a dependency, cannot be seen from one class. So `class-not-introspected` is the one finding that the compile-time check reports as a warning and never as an error: a compile error must also be a startup failure, and this class passes at startup. The startup decides. The warning goes away when the class carries `@Introspected` itself; the compile-time check has no other switch for it, short of `micronaut.graphql.tools.processor.checks=false`.
