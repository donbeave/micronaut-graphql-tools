== Rules

* Every contributor bean runs once per execution, in the order of `@Order` (or `Ordered#getOrder()`), lowest first. When there are no contributor beans the library does nothing here.
* It runs on the execution executor, after the `GraphQLExecutionInputCustomizer` and before graphql-java, inside the propagated context of the request, see <<execution,Execution>>. A contributor may therefore block and may use request-scoped beans.
* api:io.micronaut.graphql.tools.execution.GraphQLExecutionRequest[] is a read-only view of the execution: `getHttpRequest()` (null for a direct call), `getHttpResponse()` (empty on a WebSocket connection), `getTransport()` (`GraphQLTransport.HTTP`, `WEBSOCKET` or `DIRECT`), `getConnectionAttributes()` (empty except on a WebSocket connection) and `getExecutionInput()`.
* A contributor rejects an operation by throwing a `graphql.GraphQLError` (for example `GraphqlErrorException`): its error is the only error of the response, with `data` of `null`, and no resolver runs. Any other exception is logged at ERROR and the response carries one generic error, `extensions.code` `INTERNAL_ERROR`, without the message of the exception. See <<errors,Errors>>.
* State that belongs to one request lives in the context of its execution, never in a singleton: a singleton is shared by all concurrent requests.
