This page is a recipe for a Relay-style connection (`first` and `after`, edges with cursors, a page info) in a schema-first application. The library has no connection support of its own: the schema declares the connection types like any other object types, and your classes back them. The page describes a recipe, not an API: the supported parts are the annotations it uses (`@GraphQLType`, `@GraphQLRootResolver`), which the other pages describe, and the connection classes and the cursor are application code. The code is written for the example suites and tested there.

== Strict mode

The test suites run these examples with strict mode at its default, and the startup reports no finding for them: each field of the connection types is bound to a record component, a property or a resolver method, and the types are reachable from `Query.articles`.

== Limits

* The recipe backs the schema with own classes. The types of `graphql.relay` (`DefaultConnection`, `DefaultEdge`, `DefaultPageInfo`) have no introspection, and `Connection<T>` is an interface, so the recipe does not use them. A class that you wrote can carry the annotation; one of graphql-java cannot, and the recipe does not list it in `@GraphQLModels`.
* One connection type per node type: a generic class such as `Connection<T>` is not a model of this recipe, so each list has its own connection class and its own edge class. `PageInfo` is shared.
* The library does not generate connection types, cursors or the `first` and `after` arguments.
* The cursor, the paging of the data source and the `before` and `last` arguments are the application's. The example pages forward only.
