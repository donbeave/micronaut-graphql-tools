== Kotlin data classes

A Kotlin data class is a model, an input class and a parameter type. The library reads and builds it through the bean introspection that Micronaut generates at compile time, as it does a Java record.

As a model, a data class needs @api:io.micronaut.graphql.tools.annotation.GraphQLType[] and nothing else; the properties are read through the introspection:

[source,kotlin]
----
include::{dataclass-sources}/example/dataclass/DataClassFixtures.kt[tags=input]
----

The rules:

* A field that the client omits takes the default argument. A field that the client sends as `null` is `null` when the parameter type is nullable (`String?`), whatever its default argument is. A parameter with a non-null type keeps its default argument for an explicit `null`.
* Use a nullable type for a primitive parameter that the client may omit or null (`Int?`): a nullable GraphQL field mapped to a primitive fails the startup with `[nullable-primitive]`.
* A parameter of type api:io.micronaut.graphql.tools.input.ArgumentValue[] gets `ArgumentValue.omitted()` for an omitted field and `ArgumentValue.ofNullable(value)` for a present one, so its default argument is not used. See <<inputs,Inputs>>.
* Nested data classes, and lists of them, apply their own default arguments.
* A function parameter, such as `fun describe(input: AccountInput)`, takes a data class the same way.

== Other Kotlin features

* A Kotlin `suspend` function is a resolver method, see <<execution,Execution>>.
* A Kotlin method can return a `Flow<T>` for a field of the `Subscription` type, see <<subscriptions,Subscriptions>>.
