This page lists the breaking changes of each release. Each entry names the change, and the migration page gives the fix. Entries for a change that is not on `master` yet are marked _pending_.

== 1.0.0-M1

Tagged `1.0.0-M1` and published to GitHub Packages. The breaking changes are numbered `BC-01` to `BC-19`. See the migration page for what breaks and how to fix it.

* BC-01 to BC-19: see the migration page, entries for 1.0.0-M1.

== 1.0.0-M2

Tagged `1.0.0-M2` and published to GitHub Packages. The breaking changes are numbered from `BC-20`.

* #173 (BC-20): the `graphql-tools` mapper seam is internal and no longer documented. See the migration page, entries for 1.0.0-M2.

== 1.0.0-M3

Tagged `1.0.0-M3` and published to GitHub Packages. The breaking changes are numbered `BC-21` to `BC-33`. See the migration page, entries for 1.0.0-M3, for the fix of each one.

* #33 (BC-21): a bound Java enum needs a bean introspection (`@Introspected`); the startup fails without one. See the migration page, entries for 1.0.0-M3.
* #237 (BC-22): one code system for checks and errors. Messages start with `[code]`, and the `!` lines of the binding manifest are named by the code. See the migration page, entries for 1.0.0-M3.
* #37 (BC-23): arguments and input objects are converted from `BeanIntrospection`; Jackson annotations and an `ObjectMapper` stop being the input contract. See the migration page, entries for 1.0.0-M3.
* #17 (BC-24): the compile-time processor reads `*.graphqls` files only; a `*.graphql` file in the schema directory is no longer a schema file. See the migration page, entries for 1.0.0-M3.
* #90 (BC-25): the binding manifest format is specified and versioned, and moves to version 2: ASCII separators, scalar lines that name the scalar, and a schema hash that does not depend on the order of the files. See the migration page, entries for 1.0.0-M3.
* #36 (BC-26): Jackson leaves the `api` scope; an application that uses Jackson adds `micronaut-jackson-databind` itself. See the migration page, entries for 1.0.0-M3.
* #86 (BC-27): per-check severity; six old keys are removed. See the migration page, entries for 1.0.0-M3.
* #159 (BC-28): the option `micronaut.graphql.tools.input.detect-omission` is removed; declaring api:io.micronaut.graphql.tools.input.ArgumentValue[] is enough. See the migration page, entries for 1.0.0-M3.
* #105 (BC-29): the precedence value `strict` is named `fail` and `strict` is rejected; a type resolver method that declares its coordinate wins over a getter. See the migration page, entries for 1.0.0-M3.
* #109 (BC-30): api:io.micronaut.graphql.tools.exceptions.SchemaBindingException[] is the only public exception; the subclasses are internal, and the `@Internal` types left the API package `io.micronaut.graphql.tools`. See the migration page, entries for 1.0.0-M3.
* #354 (BC-31): the 15 public types of the root package `io.micronaut.graphql.tools` moved into the role packages `config`, `customizer`, `mapping`, `directive`, `input` and `manifest`; the root holds no types. See the migration page, entries for 1.0.0-M3.
* #291 (BC-32): the build runs the visitor instead of the earlier annotation processor (its classes are deleted from `graphql-tools-processor` by #144, which changes nothing else), and the compile-time options are renamed: `micronaut.graphql.tools.processor.schema.dirs` and `micronaut.graphql.tools.processor.checks` replace `micronaut.graphql.tools.sdlDir`. See the migration page, entries for 1.0.0-M3.
* #34 (BC-33): a bean that is a type resolver only through an inherited @api:io.micronaut.graphql.tools.annotation.GraphQLTypeResolver[] needs `micronaut-graphql-tools-processor` on the compiler path, because the startup no longer reads class annotations by reflection. See the migration page, entries for 1.0.0-M3.

Issue #15 (BC-19, resolver parameters bound by name): its runtime half is listed for 1.0.0-M1; the visitor applies the same rule at compile time, and #291 registers it, so a misnamed or missing resolver parameter fails the build.

== 1.0.0-M4

Tagged `1.0.0-M4` and published to GitHub Packages. The breaking changes are numbered `BC-34` to `BC-39` and `BC-49`. See the migration page, entries for 1.0.0-M4, for the fix of each one.

* #73 (BC-34): @api:io.micronaut.graphql.tools.annotation.GraphQLRootResolver[] and `@GraphQLTypeResolver` no longer carry the bean stereotype, so a resolver class needs a scope annotation of its own, for example `@Singleton`; a type resolver, also one that is annotated directly, needs `micronaut-graphql-tools-processor` on the compiler path when it has a supertype besides `Object`. The marker interfaces api:io.micronaut.graphql.tools.resolver.QueryResolver[], api:io.micronaut.graphql.tools.resolver.MutationResolver[], api:io.micronaut.graphql.tools.resolver.SubscriptionResolver[] and `TypeResolver<T>` are new. See the migration page, entries for 1.0.0-M4.
* #49 (BC-35): resolvers run on the blocking executor by default, not on the Netty event loop; `micronaut.graphql.tools.execution.executor: none` keeps the old behaviour. See the migration page, entries for 1.0.0-M4.
* #20 (BC-36): a `DataLoaderRegistry` bean fails the startup with `[data-loader-registry-bean]`; register the loaders as `BatchLoader` beans (the library creates the registry of each execution), add them in a api:io.micronaut.graphql.tools.execution.GraphQLContextContributor[], or provide your own `GraphQLInvocation`. See the migration page, entries for 1.0.0-M4.
* #32 (BC-37): the message of an unhandled exception is no longer sent to the client; the error is `Internal server error` with `extensions.code` `INTERNAL_ERROR`. Add a api:io.micronaut.graphql.tools.error.GraphQLExceptionMapper[] for the exceptions to show, or set `micronaut.graphql.tools.errors.details: true` in development. See the migration page, entries for 1.0.0-M4.
* #24 (BC-38): every `Instrumentation` bean is now installed in the `GraphQL` bean of the library, chained in bean order, before the api:io.micronaut.graphql.tools.customizer.GraphQLBuilderCustomizer[] beans run. Before, such a bean was ignored unless a customizer installed it. An application that installs an `Instrumentation` bean in a customizer too now runs it twice: remove the customizer, and give the bean an `@Order` if the order matters. See the migration page, entries for 1.0.0-M4.
* #495 (BC-39): the observability module follows the Micronaut metrics and tracing conventions. The keys moved (`micronaut.metrics.binders.graphql.*` for the metrics, `micronaut.graphql.tools.tracing.*` for the tracing, no master switch), the request span is named `query`, `mutation` or `subscription`, a field span has `graphql.field.path` and no `graphql.field.parent`, the public `PREFIX` and span attribute constants are removed, and the request span is current in the propagated context. See the migration page, entries for 1.0.0-M4.
* #570 (BC-49): the observability module is split into `micronaut-graphql-tools-micrometer` (the metrics, `GraphQLObservability` is now api:io.micronaut.graphql.tools.micrometer.GraphQLMetrics[] in `io.micronaut.graphql.tools.micrometer`) and `micronaut-graphql-tools-opentelemetry` (the spans). The keys do not change, and the library still adds one `Instrumentation` bean for both. See the migration page, entries for 1.0.0-M4.

== 1.0.0-M5

Not released yet. The changes below follow the last tagged milestone, 1.0.0-M4. They are numbered `BC-40` to `BC-47` and `BC-50` to `BC-53`; `BC-48` is not used, because the issue that reserved it (#511) made no breaking change.

* #497 (BC-40): the scalars configuration is bound to a typed class, api:io.micronaut.graphql.tools.scalars.ScalarsConfiguration[], and a key under `micronaut.graphql.tools.scalars` that is not the id of a standard scalar (a typo such as `local-dat.enabled`) now fails the startup; before it was ignored. The documented keys keep their names. See the migration page, entries for 1.0.0-M5.
* #506 (BC-46): the camel case compile-time options are renamed to dotted lowercase: `micronaut.graphql.tools.processor.resolver.accessor.prefixes`, `micronaut.graphql.tools.processor.loose.nullability` and `micronaut.graphql.tools.processor.type.class.convention` replace `resolverAccessorPrefixes`, `looseNullability` and `typeClassConvention`, and an old name fails the build with `[processor-option-removed]`. See the migration page, entries for 1.0.0-M5.
* #502 (BC-43): the extension point types that lacked the `GraphQL` prefix gain it (the runtime wiring, type definition registry, schema mapping dictionary and data loader options customizers and the field fetcher decorator). Only the names change. See the migration page, entry BC-43, for the old and new name of each.
* #498 (BC-41): `SchemaBindingException` now extends Micronaut's `ConfigurationException` (it extended `RuntimeException`), and `code()` is renamed `getCode()`. Codes and messages do not change. Replace `e.code()` with `e.getCode()` (`e.code` in Groovy and Kotlin). See the migration page, entries for 1.0.0-M5.
* #501 (BC-47): `ResolverBeanCondition` moved from `io.micronaut.graphql.tools.annotation` to `io.micronaut.graphql.tools.internal.resolver` and is `@Internal`, and `@GraphQLType.value()` is declared `Class<?>`. An application does not name either. See the migration page, entries for 1.0.0-M5.
* #504 (BC-44): one accessor style in the public types of the `websocket`, `mapping`, `directive` and `execution` packages. api:io.micronaut.graphql.tools.websocket.GraphQLConnectionRequest[] is a record, and the accessors of api:io.micronaut.graphql.tools.websocket.GraphQLConnectionResult[], api:io.micronaut.graphql.tools.execution.GraphQLExecutionRequest[], api:io.micronaut.graphql.tools.execution.GraphQLDataLoaderOptionsCustomizer[] and api:io.micronaut.graphql.tools.execution.DataLoaderBatchStatistics[] (an experimental type, see <<experimentalTypes>>) follow the bean convention (`getX`, `isX`). See the migration page, entries for 1.0.0-M5.
* #499 (BC-42): the library's `GraphQLInvocation` is no longer removed when the application declares its own. The unqualified injection point still resolves to yours, but `List<GraphQLInvocation>` and `getBeansOfType(GraphQLInvocation.class)` now also contain `LibraryGraphQLInvocation`. Two limits follow, and both fail the startup with a message that names the way out: an application invocation that is only `@Secondary` (drop `@Secondary` or make it `@Primary`), and a `GraphQL` or `GraphQLSchema` declared with `@EachBean(GraphQLInvocation.class)` unless an application `GraphQL` bean that does not depend on it is selected (target the application's own bean type). See the migration page, entries for 1.0.0-M5, and the Customization page.
* #650 (BC-50): a property under the id of a standard scalar that is not `enabled`, `name` or `format` (a typo such as `micronaut.graphql.tools.scalars.local-date.nmae`) now fails the startup with a message that names the key and lists the valid properties; before it was ignored. The documented keys keep their names. See the migration page, entries for 1.0.0-M5.
* #505 (BC-45): `manifest.record` is removed and `manifest.enabled` alone records the manifest, so that the api:io.micronaut.graphql.tools.manifest.BindingManifest[] bean can be read; it is written at startup only when `manifest.path` is also set. `checks` binds to the enum api:io.micronaut.graphql.tools.config.CheckSeverity[] and the severity and precedence values are read by the core enum conversion of Micronaut, so only its spellings (`fail`, `FAIL`, `property-first`, `PROPERTY_FIRST`) are accepted. See the migration page, entries for 1.0.0-M5.
* #691 (BC-51): a `GET` request whose selected operation is a mutation is answered with `405` and `Allow: POST` before it executes, under `application/json` and `application/graphql-response+json`; before, the mutation ran. Send a mutation with `POST`. A query over `GET`, and every operation over `POST`, is unchanged. See the migration page, entry BC-51. The TCK scenario `http-conformance` proves it in the Java, Kotlin and Groovy suites, with the upload module on and off.
* #652 (BC-52): `GraphQLRuntimeWiringCustomizer#claimedFields()` is renamed `getClaimedFields()` and `ArgumentValue#get()` is renamed `getRequired()`, so that no public package mixes accessor styles; the architecture rule now covers every public package. See the migration page, entries for 1.0.0-M5.
* #779 (BC-53): the enum accessors are renamed to the bean form, so that no public enum mixes accessor styles with the rest of the API: `BindingCode#code()`, `check()`, `compileTime()` and `summary()` are `getCode()`, `isCheck()`, `isCompileTime()` and `getSummary()`, and `StandardScalar#id()`, `defaultName()`, `javaClass()`, `group()` and `defaultFormat()` are `getId()`, `getDefaultName()`, `getJavaClass()`, `getGroup()` and `getDefaultFormat()`. The architecture rule no longer exempts enums and also covers the scalars module. See the migration page, entries for 1.0.0-M5.
