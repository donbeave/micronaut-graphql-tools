This page lists the breaking changes of each release. Each entry names the change, and the migration page gives the fix. Entries for a change that is not on `master` yet are marked _pending_.

== 1.0.0-M1

Tagged `1.0.0-M1` and published to GitHub Packages. The breaking changes are numbered `BC-01` to `BC-19`, as in the release notes. See the migration page for what breaks and how to fix it.

* BC-01 to BC-19: see the migration page, entries for 1.0.0-M1.

== 1.0.0-M2

Tagged `1.0.0-M2` and published to GitHub Packages. The breaking changes are numbered from `BC-20`, as in the release notes of 1.0.0-M2.

* BC-20 (#173): the `graphql-tools` mapper seam is internal and no longer documented. See the migration page, entries for 1.0.0-M2.

== Planned after 1.0.0-M2

These changes are planned for the milestones of the tracker. Each one is _pending_ until it lands on `master`; the migration page describes each one.

=== 1.0.0-M3

* #33 (BC-21): a bound Java enum needs a bean introspection (`@Introspected`); the startup fails without one. See the migration page, entries for 1.0.0-M3.
* #237 (BC-22): one code system for checks and errors. Messages start with `[code]`, and the `!` lines of the binding manifest are named by the code. See the migration page, entries for 1.0.0-M3.
* #37 (BC-23): arguments and input objects are converted from `BeanIntrospection`; Jackson annotations and an `ObjectMapper` stop being the input contract. See the migration page, entries for 1.0.0-M3.
* #17 (BC-24): the compile-time processor reads `*.graphqls` files only; a `*.graphql` file in the schema directory is no longer a schema file. See the migration page, entries for 1.0.0-M3.
* #90 (BC-25): the binding manifest format is specified and versioned, and moves to version 2: ASCII separators, scalar lines that name the scalar, and a schema hash that does not depend on the order of the files. See the migration page, entries for 1.0.0-M3.
* #36 (BC-26): Jackson leaves the `api` scope; an application that uses Jackson adds `micronaut-jackson-databind` itself. See the migration page, entries for 1.0.0-M3.
* #86 (BC-27): per-check severity; six old keys are removed. See the migration page, entries for 1.0.0-M3.
* #105: the default precedence becomes `fail` (_pending_).
* #109: the exception subclasses become internal behind the public `SchemaBindingException` (_pending_; the base class and its `code()` are on `master` with BC-22).
* #144: the JSR-269 code is removed from `graphql-tools-processor` (_pending_).
* #236: `AmbiguousBindingException` becomes internal (_pending_).
* #291: the visitor replaces the JSR-269 processor, and the processor options are renamed (_pending_).

Issue #15 (BC-19, resolver parameters bound by name) is open. Its runtime half is on `master` and is listed for 1.0.0-M1; its compile-time half is _pending_ with #150.
