This page records what each tagged milestone changed. The breaking changes of each release and their numbers are on the Breaking Changes page. Milestones are published to the GitHub Packages Maven registry of this repository by the `Release` workflow; they are not on Maven Central and there is no GitHub Release.

== 1.0.0-M5

=== What this release changes

* In-process tester (#215): the module `micronaut-graphql-tools-testing` runs a document with variables, context values and headers through the application's `GraphQLInvocation` in a test, and returns a response with data, errors and extensions and fluent assertions on paths and errors. See the Testing page.
* One accessor style in every public package (#652, BC-51): `GraphQLRuntimeWiringCustomizer#getClaimedFields()` and `ArgumentValue#getRequired()` replace `claimedFields()` and `get()`, and the architecture rule covers every public package.

== 1.0.0-M4

=== What this release changes

* Execution model (#44, #49): the library owns the GraphQL invocation. Each operation hops once to the executor named by `micronaut.graphql.tools.execution.executor` (default `blocking`: virtual threads on JDK 21 and later, the `io` pool on JDK 17; `none` keeps the event loop) before graphql-java runs, so parsing, validation and synchronous resolvers never run on the Netty event loop. The execution-input customizer is subscribed at subscribe time on the subscribing thread and honours cancellation (#444), the real transport (`WEBSOCKET` or HTTP) is recorded in the execution state (#448), an `executor.execute` failure becomes a failed publisher (#445), and a `@Primary` factory that returns `DefaultGraphQLInvocation` is detected as a competing invocation (#447). The propagated context is captured when `invoke` is called, not inside `deferContextual` (#560).
* Per-field executors and async boundary (#427, #428): `@ExecuteOn` on a resolver or model method names a per-field executor, decided once at startup. An async resolver that completes on an event loop thread restores the execution context and leaves the event loop before its children run. Publisher returns on non-subscription fields are adapted (#75). A field span is current in a resolver annotated with `@ExecuteOn` (#551).
* Cancellation (#429, #490): an execution is cancelled when the client disconnects, when a WebSocket operation completes and when the connection closes. Pending async stages, including Kotlin `suspend` coroutines, are cancelled and no later async field starts.
* Per-execution context (#20): `GraphQLContextContributor` beans add entries to the `GraphQLContext` once for each execution, and the library creates the `DataLoaderRegistry` of each execution lazily from `BatchLoader`, `BatchLoaderWithContext`, `MappedBatchLoader` and `MappedBatchLoaderWithContext` beans. A `DataLoaderRegistry` bean fails the startup with `[data-loader-registry-bean]`. A contributor can register loaders when there are no loader beans (#465), a `DataLoaderOptions` customizer applies per loader and caching is off for subscription loaders (#461), and the `BatchLoaderEnvironment` context is covered by a suite (#547).
* Injectable resolver parameters (#22): a resolver method can declare the `GraphQLContext`, the `DataFetchingEnvironment`, the selection set, a typed `DataLoader<K, V>` (matched by type, also for Kotlin wildcard element types, #460), a `Principal` or `Authentication`, and the HTTP request and response; the library binds them by type and annotation. See the Resolver Parameters page.
* Field decorator SPI (#19): `FieldFetcherDecorator` beans decide once for each field, at startup, whether to wrap its fetcher; a field that no decorator selects keeps the fetcher it had. The decorator cost is measured by JMH cases on a 1,050-field query (#482), with the idle-machine numbers recorded (#532).
* Protection and limits (#25): `micronaut.graphql.tools.protection.document-cache-size` (a parsed-and-validated document cache, default 1000, `0` is off), `max-depth` and `max-complexity` (rejected before any resolver runs, `0` is no limit), `introspection` (`false` hides `__schema` and `__type`) and `micronaut.graphql.tools.execution.timeout` (the client gets `EXECUTION_TIMEOUT` and the execution is cancelled; a running resolver is not interrupted). Without a timeout key an operation pays nothing for it. A customizer subscription that never completes is disposed when the timeout fires before it is assigned (#579). See the Protection page.
* Default error handling (#32): the message of an unhandled exception is hidden (`Internal server error`, code `INTERNAL_ERROR`), `GraphQLExceptionMapper` beans map an exception type to an error with a message and extensions, by order, matching the real exception of a failed `CompletionStage`; `GraphQLErrorsCustomizer` changes the final list of errors; a `ConstraintViolationException` becomes one error for each violation with its argument path. `micronaut.graphql.tools.errors.details` shows the message in development, `micronaut.graphql.tools.errors.stack-traces` adds the stack trace to the log entry. Subscription event results and publisher errors go through the same handler and customizers (#469), an error with an empty path or locations gets the field path and location (#470), `GraphQLExceptionContext.getSourceLocation` is nullable and never adds a null location (#471), and the customizer chain contract for an empty list is settled (#472). The constraint violation mapping is tested with a real Micronaut Validation run (#468), orders paths correctly, keeps raw map keys and container-element names (#545), and keeps custom labels and angle-bracket extractor names (#582). See the Errors page.
* WebSocket transport (#29): `graphql-transport-ws` support (`graphql.graphql-ws.enabled`, `.path`, `.connection-init-wait-timeout`), `GraphQLConnectionInterceptor` beans that accept or reject a connection at `connection_init`, and per-session state: a session owns its operations, an operation that completes leaves the session and its id can be reused, and a close cancels the operations that still run. A connection that sends no `connection_init` in time closes with code `4408`. The keep-alive sender of the deprecated Apollo sub-protocol is no longer a bean while that support is off (#549). The WebSocket request, response and principal parameters are tested and documented (#534, #567), and the HTTP and WebSocket suites cover startup failure and concurrent requests (#50).
* Security module (#21, #23): `micronaut-graphql-tools-security` puts the `Authentication` in the context and in resolver parameters, guards resolver methods and classes with `@Secured` (`IS_ANONYMOUS`, `IS_AUTHENTICATED`, roles, `DENY_ALL`; the decision is made once for each field at startup, with `UNAUTHENTICATED` and `FORBIDDEN` error codes) and calls `RootFieldsHook` beans with the root fields of a parsed operation. `micronaut.graphql.tools.security.enabled` (default `true`) switches the module off, a replaced `RolesFinder` bean is honoured (#587), and an expression-form `@Secured` value is rejected at startup with a message that names the resolver method (#586). The core library does not depend on Micronaut Security. See the Security page.
* HTTP access (#23): a resolver reads the `HttpRequest` of the operation and changes the `MutableHttpResponse` (a header or a cookie reaches the client), as method parameters. Over WebSocket the request is the upgrade request, `Optional<MutableHttpResponse<?>>` is empty, and a plain response parameter is an error of the field with `HTTP_RESPONSE_UNAVAILABLE`. See the HTTP Access page.
* File upload (#47): the module `micronaut-graphql-tools-upload` implements the GraphQL multipart request specification: an `Upload` scalar and a `multipart/form-data` route on the endpoint path. An invalid request is rejected: a `map` path without a `null` placeholder, or an `operations` part without a query (#544). The guide covers decoding on the event loop and CSRF. `micronaut.graphql.tools.upload.enabled` switches it off.
* Standard scalars (#46): the module `micronaut-graphql-tools-scalars` registers the `java.time` scalars, JSON and a selection of extended scalars, so a schema only declares `scalar LocalDate`. Date patterns accept the optional-era forms (#450); the JSON scalar rejects NaN and infinity nested in a value (#449) and a float literal that underflows to zero (#455), keeps integral `Number` types exact (#456) and no longer overflows the stack on a cyclic programmatic variable (#531).
* Observability (#24, #495): every `Instrumentation` bean is installed in the `GraphQL` bean of the library, chained in bean order. Metrics and tracing follow the Micronaut conventions: `micronaut.metrics.binders.graphql.*` for the metrics and `micronaut.graphql.tools.tracing.*` for the spans, built on the OpenTelemetry `Instrumenter` API, with the field span selection on the field decorator SPI (#483). The module is split by technology (#570): `micronaut-graphql-tools-micrometer` and `micronaut-graphql-tools-opentelemetry`, with one `Instrumentation` bean in `graphql-tools` for both. See the Observability page.
* Models and type system (#68, #70, #76, #180): `@GraphQLModels` introspects external and generated model classes, and carries every declared `@Introspected` member (`accessKind`, `includes`, `excludes`) over when it re-annotates a class (#588); it keeps its introspections when another processor re-annotates `@Introspected` (#528) and warns on classes and packages that two annotations name (#589). Union members and interface implementations are derived from `implements` relations and a naming convention (#70) and from the permitted subclasses of a sealed type (#487). Kotlin data classes and default arguments work as models, inputs and parameters (#180).
* Interfaces and markers (#71, #73, #74, #77, #454, #563): an interface type resolver applies to an interface that no field returns, abstract-type ambiguity is detected at startup, and the lookup mode of an interface-mapped type is logged. The resolver marker interfaces `QueryResolver`, `MutationResolver`, `SubscriptionResolver` and `TypeResolver<T>` in the package `io.micronaut.graphql.tools.resolver` (#73) fix the root operation type and give the source type as a type argument with no class literal; only the methods that implement a method of a contract interface bind, so a public helper binds nothing and does not trip strict mode. The visitor of `graphql-tools-processor` records the operations, the source type and the contract methods in the annotation metadata of the implementation (refined in #454), and a bean that mixes a root marker with a `TypeResolver` contract binds each method on its own side (#563). The startup and the compile-time checks use the same rules.
* Kotlin and Groovy runtime (#181, #182, #183, #184, #185): Kotlin `Flow` on subscription fields is adapted to a `Publisher` once for each field, collected once for each subscription in the propagated context and cancelled with it; a `Flow` without kotlinx-coroutines-reactive fails with `[flow-without-reactive-coroutines]`. A Kotlin `suspend` resolver binds as an async field with the propagated context visible in the coroutine, and fails with `[suspend-without-coroutines]` without kotlinx-coroutines-core. The support is a bean that exists only when the Kotlin classes are on the classpath, so a Java-only application links no Kotlin type. A Groovy field of `String` may use `GString` as its Java type, Groovy-generated properties bind as getters and input setters, and Groovy 4 `sealed` interfaces work as unions and interfaces. See the Groovy page.
* Compile-time checks (#146, #183, #404, #405, #406, #419, #439, #459, #486, #563, #564, #565): Kotlin nullability is checked against schema nullability (also under kapt, from Kotlin metadata or nullable stub annotations); a Kotlin `internal` resolver method is checked against its mangled JVM name; a package-private resolver method is reported, and an unbound non-public resolver method says to make it private (#438); union member and interface implementation classes that an annotation maps, and FIELD-access models, are checked; `unmapped-input-property` is reported under KSP for settable Kotlin input properties; `Completable` on a non-null field has a rule; the visitor and the startup agree on a raw `CompletionStage` return type and on a schema with no schema definition and no Query type; resolvers exposed by a factory, including Java records, are checked; and the suspend-aware arity is used under kapt. The processor options guide and the Maven sample build cover `looseNullability` and the build-tool snippets (#484, #546).
* Native image (#62, #151, #536, #550, #568): every feature category has a native test in the Java and Kotlin suites, a native-covered case for an unreturned interface resolver, and the HttpTck, protection and http scenarios run natively. Native images are built with shared-arena support, so the security tests log no `Arena.ofShared` error from event-loop threads, and the Kotlin suite runs KSP in full (#566).
* Build and CI (#407, #410, #411, #412, #418, #530, #535, #569): the class loader leak of the corpus test JVM is fixed, the kapt corpus batch compile is isolated per worker, and the Compressed class space use is measured on JDK 27 before and after (#535). `gradle-profiler` scenarios and a compile-time budget measure the cost of the compile-time checks (#418). A guard script checks that every list of modules agrees with `settings.gradle.kts` (#569). The canary failures on JDK 27, graphql-java latest and Kotlin latest are fixed, and dependency downloads are retried.
* Benchmarks (#417, #430, #482, #532, #533, #574): JMH cases measure the execution hop (event loop direct, one hop per request, a hop per field), the per-class binding rules (`BindingRulesBenchmark` on a `ClassElement` fixture) and field decorators. The `invocationOverhead` and `observedInvocationSlope` allocation gates now subscribe to the `Mono`, so they measure the request.

* Resolver marker interfaces (#73): `QueryResolver`, `MutationResolver`, `SubscriptionResolver` and `TypeResolver<T>` in the package `io.micronaut.graphql.tools.resolver`. A marker fixes the root operation type (the root type that the schema names for the operation), `TypeResolver<T>` gives the source type as a type argument with no class literal, and only the methods that implement a method of a contract interface bind, so a public helper of an implementation binds nothing and does not trip strict mode. The visitor of `graphql-tools-processor` records the operations, the source type and the contract methods in the annotation metadata of the implementation, and the startup reads them from the bean definition. The reflective read of a class annotation in the registry is removed. The compile-time checks and the startup use the same rules for the markers.
* Kotlin `Flow` on subscription fields (#181): a method of a `Subscription` field can return a `Flow<T>`. The library adapts it to a `Publisher` once for each field at startup, collects it once for each subscription in the propagated context of the operation, and cancels the collection when the subscription is cancelled. A `Flow` on any other field fails the startup. The adapter exists only when kotlinx-coroutines-reactive is on the classpath; binding a `Flow` subscription without it fails the startup with `[flow-without-reactive-coroutines]`.
* Kotlin `suspend` resolvers (#185): a `suspend` function binds as a query, mutation or type resolver method, its continuation is not a parameter, and the field is an async field. The support is a bean of the library that exists only when the Kotlin and kotlinx-coroutines classes are on the classpath, so a Java-only application and its native image link no Kotlin type. The propagated context is visible inside the coroutine, an exception becomes an error of the field, and cancelling the field cancels the coroutine. Binding a `suspend` function without kotlinx-coroutines-core fails the startup with `[suspend-without-coroutines]`.
* Default error handling (#32): the message of an unhandled exception is hidden (`Internal server error`, code `INTERNAL_ERROR`), `GraphQLExceptionMapper` beans map an exception type to an error with a message and extensions, by order, matching the real exception of a failed `CompletionStage`; `GraphQLErrorsCustomizer` changes the final list of errors; a `ConstraintViolationException` becomes one error for each violation with its argument path. `micronaut.graphql.tools.errors.details` shows the message in development, `micronaut.graphql.tools.errors.stack-traces` adds the stack trace to the log entry. See the Errors page.
* Groovy runtime (#182): a field of `String` may declare Groovy's `GString` as its Java type, as a result, as the element of a `CompletionStage`, or as a property getter. The library adds no conversion step: graphql-java's `String` scalar serializes it with `toString()`. Properties that Groovy generates bind as getters and as input setters, and Groovy 4 `sealed` interfaces work as unions and interfaces. See the Groovy page.

=== Other behaviour changes

* By default every operation runs on the `blocking` executor, so a blocking resolver no longer stalls the server. With `micronaut.graphql.tools.execution.executor: none` there is no hop and the operation runs on the receiving thread, as before. The `GraphQLExecutionInputCustomizer` is the one step that runs on the subscribing thread.
* A resolver class annotated only with `@GraphQLRootResolver` or `@GraphQLTypeResolver` is no longer a bean, so add a scope annotation such as `@Singleton`.
* A WebSocket operation has the upgrade request as its request. A plain `MutableHttpResponse` parameter over WebSocket is an error of the field with `HTTP_RESPONSE_UNAVAILABLE`.
* A multipart request that is not valid is rejected with an error before the invocation runs.

=== Known limitations

* A resolver that is already running is not interrupted by a timeout or a client disconnect; only the continuation of its async fields and later async fields are aborted.
* `protection.introspection: false` hides the schema fields from clients; it replaces a field visibility that the application set on the schema, and it is not an access control.
* An expression-form `@Secured` value is rejected at startup; the security module decides on roles and the authentication state only.

== 1.0.0-M3

=== What this release changes

* Input omission (#159): `ArgumentValue` needs no option. The converter of an input type handles omission only when that type has an `ArgumentValue` property or constructor parameter; a type without one runs no omission code, and a `List<String>` argument allocates nothing for it (the allocation baselines are unchanged).
* Precedence (#105): one rule for object and interface fields. A field that a member of the Java type and a type resolver method can both bind fails the startup under `precedence: fail` (the new name of the default `strict`), and the type resolver method wins, with no ambiguity, when the field carries a resolver directive or the method declares its coordinate with `@GraphQLSchemaCoordinate`; a member marked `@GraphQLIgnore` binds nothing. `precedence` stays independent of `strict`. Decided at startup; the request path is unchanged.
* Renaming a binding (#107): `@GraphQLField("name")` on a method or a property of a type class binds the field of that name (a field named `class`, `default`, `new` or `hashCode` can be bound), `@GraphQLSchemaCoordinate` accepts a method with another name, and `micronaut.graphql.tools.resolver-accessor-prefixes` (off by default) lets `getX` and `isX` resolver methods bind the field `x`. A renamed member and another member for one field fail the startup with `multiple-methods-found` and the coordinate. The startup and the compile-time checks decide with the same rules (`micronaut.graphql.tools.processor.resolverAccessorPrefixes` for the visitor); no existing binding changes, and the request path is untouched.
* Dictionary customizers (#109): an application may define several `SchemaMappingDictionaryCustomizer` beans. They run in `@Order` on one dictionary. Before, a second bean failed the startup with `NonUniqueBeanException`.
* Compile-time options renamed (#291): the build runs the visitor, and `micronaut.graphql.tools.processor.schema.dirs` and `micronaut.graphql.tools.processor.checks` replace `micronaut.graphql.tools.sdlDir`. A resolver parameter that has no argument of its name fails the build with `[argument-mismatch]` (#15). `[class-not-introspected]` stays a compile-time warning, because an `@Introspected(classes = ...)` declaration elsewhere can still make the enum introspected; with `-Werror` the warning fails the build.
* Inherited type resolver contracts (#34): the visitor of `graphql-tools-processor` records the contracts that a type resolver bean inherits in its annotation metadata, and the startup reads them from the bean definition instead of reading class annotations by reflection. A bean that is a type resolver only through an inherited annotation needs the processor; without it the startup fails with `[type-resolver-contracts-not-found]`.
* Public API (#109): `SchemaBindingException` is the only public exception class; the 43 subclasses are internal, and the `@Internal` types left `io.micronaut.graphql.tools` for `io.micronaut.graphql.tools.internal` (the runtime `processor` package is `internal.registry`). Besides `code()` it has `getCoordinate()`, `getMappingContext()`, `getFailures()` (the failures of `binding-failures`) and `getCodes()` (the checks of `strict-findings`). The code tables of the error reference page are generated from `BindingCode`, and a spec fails when they differ.
* Role packages (#354): the public types of `io.micronaut.graphql.tools` moved to `config`, `customizer`, `mapping`, `directive`, `input` and `manifest`; the root package holds no types. Imports change; behaviour does not.
* Performance: a GraphQL enum is wired with a values provider built at startup from the enum's bean introspection, so an enum argument reaches the resolver as the Java constant without a conversion call. The allocation baseline of the enum argument case drops from 504 B to 24 B (#33).
* Performance: arguments and input objects are converted by converters that startup builds from the declared type and the bean introspection, so a request runs no Jackson `convertValue` and no reflection. The allocation baselines drop, per operation: a scalar argument 504 B to 24 B, an input object 728 B to 48 B, a list of four input objects 1,648 B to 176 B (#37).
* Safety (#86): per-check severity. `micronaut.graphql.tools.checks.<code>` is `fail` (the default), `warn` or `ignore` for each of the ten checks, `strict` is the shorthand for the checks without an entry, and `allow.unreachable`, `allow.inert-directives`, `allow.schema-customizer-directives` and `allow.findings` (lines of the binding manifest) accept findings. Every entry is validated at startup. A check at `ignore` does no work. Documented in the configuration reference and the migration page.
* Diagnostics: one code registry for the strict checks and the startup failures, `BindingCode` in `graphql-tools-binding` (#237). Every startup message starts with `[code]`, `SchemaBindingException#code()` returns it, the `!` lines of the binding manifest are named by it, and the compile-time diagnostics use the same codes. The error reference lists them.
* Schema discovery (#17): without a `TypeDefinitionRegistry` bean the library reads `micronaut.graphql.tools.schema.locations` (default `classpath:graphql/**/*.graphqls`; `classpath*:` for dependency jars, `file:` for the file system) and merges the files, each parsed with its own name. A schema without a `schema { }` block uses `Query`, `Mutation` and `Subscription` as root types. A file that holds only operations is skipped. A native image reads the schema index `META-INF/micronaut-graphql-tools/schema-index.txt`. The compile-time processor reads its schema directory with the same code.
* Input conversion errors (#175): a value that does not convert (a custom scalar value that is not accepted, a list where a `Map` is declared, an input class that rejects a value) is a GraphQL error of the field with `extensions.code` `INPUT_CONVERSION_FAILED`, the coordinate `Type.field(argument)` and the path inside the value. The message has no Java class name and no stack detail; the cause is logged at debug level. The other fields still resolve. Before, the raw exception message reached the client in graphql-java's generic data fetching error.
* Argument names (#15): the compile-time visitor binds parameters to arguments by name with the rule that the startup uses, so both report `argument-mismatch` with the same coordinate. A parameter of a method inherited from a class file that has no parameter names (built without `-parameters`, or without `-g` for a method with a body) is `arg0`; the failure then says to compile the class with `-parameters` or to use `@GraphQLArgument`. A resolver method declared in the processed class needs no `-parameters`. The name-to-position plan is built at startup; the request path is unchanged.
* Binding manifest: the format is specified in the guide page "Binding Manifest" and versioned in its first line, `# graphql-binding-manifest 2` (#90). The schema hash does not depend on the order of the schema files and extensions, a `scalar` line names the scalar and not the `Coercing` class, the text is ASCII, and the examples of the specification are golden files. A start that does not record the manifest still costs nothing. The graphql-java line of the header stays `unknown` on graphql-java 26, whose jar declares no version.
* Compile-time checks: `graphql-tools-processor` runs an isolating `TypeElementVisitor` (#150, #144) that checks each resolver class against the schema with the rules the startup uses (`graphql-tools-binding`): method-to-field matching, arguments by name, return types, input types and enums a resolver reaches, resolvers spread over several modules (#147), conditional resolver beans, and inherited type resolver contracts. It warns where a check cannot prove its finding. Incremental compilation is proven by a differential build per language, and the Kotlin cases run under KSP2 (#143). The new guide page "Compile-time verification" (#12) describes the checks, the options and the build setup for Gradle and Maven; the sample projects in `test-suite-build` build with Gradle TestKit and `mvn`.
* Module layout: the rule bodies moved into the new module `graphql-tools-binding` (#339, `@Internal` types), the runtime wiring generator is split by phase, and every module has a README and a module map (#357). Every package has a `package-info`, the guide has an API map page, and architecture specs fail on reflection, Jackson and public API leaks (#369, #387).
* Directive checks (#334): schema-level places, patterns and a mode switch for the directive checks.
* Argument omission API (#329, #332): `ArgumentValue` has `asOptional` and `ifPresent`, and `OptionalInt`, `OptionalLong` and `OptionalDouble` return types are unwrapped.
* Binding fixes: an overridden method of an abstract resolver superclass binds once (#335); resolver bean scopes are honoured and the registry is kept for repeated schema builds (#340); the abstract methods of an introduction advice resolver stay bindable (#341); `@Replaces` and `@EachBean`/`@EachProperty` beans are judged in the library bean selection (#346); a type named `schema` and a stale schema-customizer entry are reported correctly (#343); unmapped input properties are checked per class, so one class can serve several input types (#177); a 1,000-type chain binds without a stack overflow, and quadratic startup work is removed (#361, #365); merged omission plans keep `ArgumentValue` for a shared class; Query, Mutation and Subscription fields of one name bind to their own root methods.
* Startup performance: the customizer replacement snapshot is skipped when no user customizer exists (#351), and the start-up benchmarks gained 3,000 and 20,000 field sizes, an interface-heavy schema, retained-heap measurements and a nightly report (#296, #338, #399).
* Tests and CI: the Groovy example application has a native smoke test (#333), the serde null-field tests run natively (#330), and the TCK covers enums, error mapping and bean scopes. One required gate: every job of `gradle.yml`, the native image jobs included, is in `required checks` and runs on every event, so the pull request check is the master check (#408); the canary is scheduled only. Source files carry checked license headers, and a guard rejects references to planning notes.

=== Other behaviour changes

* An application with no `TypeDefinitionRegistry` bean now reads the default schema location instead of failing with a missing bean. When no file is found the startup fails with `[schema-not-found]`.
* A schema without a `schema { }` block binds. Before, `[schema-definition-not-provided]` failed it; it now fails only a schema that has no `Query` type.

=== Known limitations

* The five compile-time checks are not relaxed by `checks.<code>`: the compile-time error stays. The compile-time options are the four `micronaut.graphql.tools.processor.*` keys.
* `[class-not-introspected]` is a compile-time warning, not an error, because a class can be made introspected by another class (`@Introspected(classes = ...)`) or a dependency, which a check of one class cannot see. A build that turns warnings into errors (`-Werror`) fails on it.

== 1.0.0-M2

=== What this release changes

The binding stack of M1 becomes faster to start and easier to diagnose, and the build and CI move to the version policy. Issue numbers refer to this repository.

* Startup and diagnostics:
** The schema is bound when the application context starts, so a broken binding fails the startup, not the first request (#51). `micronaut.graphql.tools.eager-init: false` restores lazy binding.
** Unreachable types, invalid schema coordinates and strict findings are reported in one aggregated startup error (#84).
** An abstract-type member mapping that is ambiguous fails the startup (#77), and abstract types resolve to the most specific member (#78).
** A directive wired by both a `named` and an `everyElement` `SchemaDirective` fails the startup with `DuplicateDirectiveWiringException` (#164).
** A customizer that shadows a library-bound field is reported with the coordinate, the customizer and the fix (#166). Several startup errors name their fix (#247).
** Allowing or ignoring an unreachable type also covers the enums, inputs and scalars it uses (#83, runtime half; the compile-time half is open).
** Escape hatches: `@GraphQLIgnore`, and lifecycle methods (`@EventListener`, `@Scheduled`, `@PreDestroy`) no longer count as unbound methods in strict mode (#106, runtime half; the compile-time half is open). `RuntimeWiringCustomizer#claimedFields()` is available (#67). A bare `GraphQLScalarType` bean that is named like a schema scalar is named in the missing-scalar error with the `GraphQLScalarMapping.of` fix (#176).
** The conditional `GraphQL` and `GraphQLSchema` beans step aside only for an unqualified or `@Primary` application bean, and log the decision (#165).
** The binding manifest is recorded only when `micronaut.graphql.tools.manifest.record` or `manifest.enabled` is `true`, and rendered without reflection (#91, #64).
** A class that backs two input types keeps `ArgumentValue` for both (#160).
* Performance: per-field fetchers and argument plans are precomputed (#287), abstract types resolve through a `ClassValue` cache (#69), the object-method check uses a fixed signature set (#92). A JMH `benchmarks` module with allocation gates measures the request hot path, and a benchmark measures binding time and retained heap at 100, 1,600 and 10,000 fields (#43, #39 in part).
* graphql-java: legs are named by role: floor 21.5, default 22.4 (managed by `micronaut-graphql` 4.8.0) and ceiling 26.2 (#11, #260). The removed `DirectiveInfo` is replaced. A canary workflow tests JDK 27 and the newest graphql-java (#114).

=== Other behaviour changes since 1.0.0-M1

These changes have no BC number. Each can fail an application that started on 1.0.0-M1; the error names the fix.

* Eager binding (#51): a broken binding now fails the startup. Opt-out: `micronaut.graphql.tools.eager-init: false`.
* Ambiguous abstract-type mapping (#77) and a directive wired by both a `named` and an `everyElement` bean (#164) fail the startup. No opt-out.
* The binding manifest is no longer recorded by default (#91). Opt-in: `micronaut.graphql.tools.manifest.record: true` (or `manifest.enabled`). A `BindingManifest` bean without it fails with a message that names the key.
* A qualified second `GraphQL` or `GraphQLSchema` bean no longer disables the library's bean (#165).

=== Known limitations

* *Native image.* Native tests run on Oracle GraalVM 25 in CI. Issue #285 (the native image selecting `JacksonDatabindMapper` over the Serde mapper) is open for 1.0.0-M3.
* *Annotation processor.* The limitations listed in the 1.0.0-M1 notes still apply. The processor and the startup check do not agree on every case of unreachable types (#83) and of a superclass root-resolver method (#226); both are open for 1.0.0-M3.
* *Input conversion.* The input conversion still goes through a Jackson `ObjectMapper` internally. It is not configurable through a public bean until #37 replaces it.
* *Publishing.* Only GitHub Packages milestone versions are published, and downloading needs a token with `read:packages` even though the packages are public. See README.md#consuming-milestone-previews[Consuming milestone previews].

== 1.0.0-M1

=== What this release changes

The stack makes the binding between the SDL schema and the Java code safe: drift between the two fails the build (annotation processor) or the application startup, not a request at runtime.

* Build on Java 21; CI builds and tests graphql-java 21.3 and 25.1 (#2).
* Type system: SDL interfaces, Java interfaces as object types, union and interface member resolution (#3).
* Inputs and scalars: scalar SPI (`GraphQLScalarMapping`), generic argument conversion, `ArgumentValue` to tell an omitted argument from `null` (#4).
* Public seams: registry, wiring and schema customizers, `GraphQLBuilderCustomizer`, `SchemaDirective` wirings, a conditional `GraphQL` bean (#5, integrated by #242).
* Binding safety: explicit precedence, root resolvers per operation type, every binding failure reported at once, binding manifest, strict mode (#6).
* Compile-time verification: new module `micronaut-graphql-tools-processor` checks the SDL against the Java bindings (#7).
* Build tooling: the newest Micronaut 4 line (core 4.10.37, platform 4.10.24 for the `test-suite-*` modules, micronaut-test 4.10.3), Gradle 9.9.1 with a verified wrapper checksum, Groovy 4.0.33 forced on every configuration, Shadow 8.3.11, Apollo 4.4.4 and JMH plugin 0.7.4 (#115). Native image tests and the `test-suite-java` and `test-suite-kotlin` native Dockerfiles move from GraalVM 21 to Oracle GraalVM 25; the library still compiles to Java 17 bytecode.
