The `micronaut-graphql-tools-client` module is the GraphQL client of the library: a runtime for an application that calls a GraphQL server. It runs on the Micronaut HTTP client, so `micronaut.http.services.<id>.*`, filters and TLS apply unchanged, and it works the same from Java, Kotlin and Groovy. It is a client for applications that call a server; the server side of the library is described in the other pages of this guide. The client is new in the 1.0 line, and it is not in a tagged milestone yet: the release history will name the milestone that ships it.

== Two clients

The module offers two ways to call a server. They share the request, the response, the errors and the configuration.

* The <<clientLowLevel,low-level client>>, api:io.micronaut.graphql.tools.client.GraphQLHttpClient[], sends a `GraphQLRequest` that your code builds, with a document and variables of your own, and returns a `GraphQLResponse`. The call is reactive, a `CompletableFuture` or blocking. Use it when the document is dynamic.
* The <<clientDeclarative,declarative client>> is an interface that you annotate with `@GraphQLClient` and `@GraphQLOperation`. Micronaut implements it at compile time, and the annotation processor checks each document against the schema of the server, so a wrong field, variable or result type fails the build. Use it for a fixed set of operations.

A declarative client can return the payload of the operation, or the whole response with its errors, as a value, a `CompletableFuture`, a `Publisher`, a Reactor type or a Kotlin `suspend` function and `Flow`.

== Add the module

[source,groovy]
----
implementation("io.micronaut.graphql.tools:micronaut-graphql-tools-client")
implementation("io.micronaut.serde:micronaut-serde-jackson")
----

The version comes from the `micronaut-graphql-tools-bom` import of the <<quickStart,quick start>>. The client does not bring a JSON codec: it needs Micronaut Serialization with its JSON implementation, and fails the first client that it creates with a `ConfigurationException` when it is missing. The module has no dependency on graphql-java, on the server of the library or on Jackson, and a build check keeps it so. It exposes the JSpecify annotations (`org.jspecify:jspecify`, annotations only) as an API dependency, because the client models that the <<codegen,code generator>> writes use them for nullability.

Two modules are optional. `micronaut-retry` adds `@Retryable` for the <<clientErrorHandling,retries>> of a call, and `micronaut-reactor` adds `Mono` and `Flux` as the return types of a declarative method. A declarative client also needs the annotation processor `micronaut-graphql-tools-processor`, set up as the <<compileTimeSetupClient,build page>> describes, with the directory of the client schema in `micronaut.graphql.tools.processor.client.dirs`.

== The public API

The public types of the client are in three packages, and everything under `io.micronaut.graphql.tools.client.internal` is internal. The <<publicApi,Public API>> page lists each type.

[cols="3,2,5", options="header"]
|===
| Package | Audience | Types

| `io.micronaut.graphql.tools.client` | Public API | `GraphQLHttpClient`, `GraphQLRequest`, `GraphQLResponse`, `GraphQLSession`, `GraphQLError`, `OperationType`, `GraphQLMediaTypes`, `GraphQLClientAttributes`
| `io.micronaut.graphql.tools.client.annotation` | Public API | `@GraphQLClient`, `@GraphQLOperation`, `@GraphQLVariable`
| `io.micronaut.graphql.tools.client.exceptions` | Public API | `GraphQLClientException`, `GraphQLErrorsException`, `GraphQLTransportException`
| `io.micronaut.graphql.tools.client.internal` and its subpackages | Internal | The call path, the introduction advice, the Serde codec and the operation metadata
|===

The API names no graphql-java, graphql-tools, Jackson or Reactor type.
