# micronaut-graphql-tools 1.0.0-M4 release notes

Tag: `1.0.0-M4`, published to the GitHub Packages Maven registry of this repository by the `Release` workflow. It is not on Maven Central and there is no GitHub Release. This milestone follows [1.0.0-M3](RELEASE-NOTES-1.0.0-M3.md). The numbering of the breaking changes continues from the M3 notes.

The numbering of the breaking changes continues from the M3 notes: `BC-34` to `BC-39` and `BC-49` are the numbered changes of this milestone. See the migration page for the fix of each change.

## What this release changes

- Execution model (#44, #49, BC-35): the library owns the GraphQL invocation. Each operation hops once to the executor named by `micronaut.graphql.tools.execution.executor` (default `blocking`: virtual threads on JDK 21 and later, the `io` pool on JDK 17; `none` keeps the event loop) before graphql-java runs, so parsing, validation and synchronous resolvers never run on the Netty event loop. The execution-input customizer is subscribed at subscribe time on the subscribing thread and honours cancellation (#444), the real transport (`WEBSOCKET` or HTTP) is recorded in the execution state (#448), an `executor.execute` failure becomes a failed publisher (#445), and a `@Primary` factory that returns `DefaultGraphQLInvocation` is detected as a competing invocation (#447). The propagated context is captured when `invoke` is called, not inside `deferContextual` (#560).
- Per-field executors and async boundary (#427, #428): `@ExecuteOn` on a resolver or model method names a per-field executor, decided once at startup. An async resolver that completes on an event loop thread restores the execution context and leaves the event loop before its children run. Publisher returns on non-subscription fields are adapted (#75). A field span is current in a resolver annotated with `@ExecuteOn` (#551).
- Cancellation (#429, #490): an execution is cancelled when the client disconnects, when a WebSocket operation completes and when the connection closes. Pending async stages, including Kotlin `suspend` coroutines, are cancelled and no later async field starts.
- Per-execution context (#20, BC-36): `GraphQLContextContributor` beans add entries to the `GraphQLContext` once for each execution, and the library creates the `DataLoaderRegistry` of each execution lazily from `BatchLoader`, `BatchLoaderWithContext`, `MappedBatchLoader` and `MappedBatchLoaderWithContext` beans. A `DataLoaderRegistry` bean fails the startup with `[data-loader-registry-bean]`. A contributor can register loaders when there are no loader beans (#465), a `DataLoaderOptions` customizer applies per loader and caching is off for subscription loaders (#461), and the `BatchLoaderEnvironment` context is covered by a suite (#547).
- Injectable resolver parameters (#22): a resolver method can declare the `GraphQLContext`, the `DataFetchingEnvironment`, the selection set, a typed `DataLoader<K, V>` (matched by type, also for Kotlin wildcard element types, #460), a `Principal` or `Authentication`, and the HTTP request and response; the library binds them by type and annotation. See the Resolver Parameters page.
- Field decorator SPI (#19): `FieldFetcherDecorator` beans decide once for each field, at startup, whether to wrap its fetcher; a field that no decorator selects keeps the fetcher it had. The decorator cost is measured by JMH cases on a 1,050-field query (#482), with the idle-machine numbers recorded (#532).
- Protection and limits (#25): `micronaut.graphql.tools.protection.document-cache-size` (a parsed-and-validated document cache, default 1000, `0` is off), `max-depth` and `max-complexity` (rejected before any resolver runs, `0` is no limit), `introspection` (`false` hides `__schema` and `__type`) and `micronaut.graphql.tools.execution.timeout` (the client gets `EXECUTION_TIMEOUT` and the execution is cancelled; a running resolver is not interrupted). Without a timeout key an operation pays nothing for it. A customizer subscription that never completes is disposed when the timeout fires before it is assigned (#579). See the Protection page.
- Default error handling (#32, BC-37): the message of an unhandled exception is hidden (`Internal server error`, code `INTERNAL_ERROR`), `GraphQLExceptionMapper` beans map an exception type to an error with a message and extensions, by order, matching the real exception of a failed `CompletionStage`; `GraphQLErrorsCustomizer` changes the final list of errors; a `ConstraintViolationException` becomes one error for each violation with its argument path. `micronaut.graphql.tools.errors.details` shows the message in development, `micronaut.graphql.tools.errors.stack-traces` adds the stack trace to the log entry. Subscription event results and publisher errors go through the same handler and customizers (#469), an error with an empty path or locations gets the field path and location (#470), `GraphQLExceptionContext.getSourceLocation` is nullable and never adds a null location (#471), and the customizer chain contract for an empty list is settled (#472). The constraint violation mapping is tested with a real Micronaut Validation run (#468), orders paths correctly, keeps raw map keys and container-element names (#545), and keeps custom labels and angle-bracket extractor names (#582). See the Errors page.
- WebSocket transport (#29): `graphql-transport-ws` support (`graphql.graphql-ws.enabled`, `.path`, `.connection-init-wait-timeout`), `GraphQLConnectionInterceptor` beans that accept or reject a connection at `connection_init`, and per-session state: a session owns its operations, an operation that completes leaves the session and its id can be reused, and a close cancels the operations that still run. A connection that sends no `connection_init` in time closes with code `4408`. The keep-alive sender of the deprecated Apollo sub-protocol is no longer a bean while that support is off (#549). The WebSocket request, response and principal parameters are tested and documented (#534, #567), and the HTTP and WebSocket suites cover startup failure and concurrent requests (#50).
- Security module (#21, #23): `micronaut-graphql-tools-security` puts the `Authentication` in the context and in resolver parameters, guards resolver methods and classes with `@Secured` (`IS_ANONYMOUS`, `IS_AUTHENTICATED`, roles, `DENY_ALL`; the decision is made once for each field at startup, with `UNAUTHENTICATED` and `FORBIDDEN` error codes) and calls `RootFieldsHook` beans with the root fields of a parsed operation. `micronaut.graphql.tools.security.enabled` (default `true`) switches the module off, a replaced `RolesFinder` bean is honoured (#587), and an expression-form `@Secured` value is rejected at startup with a message that names the resolver method (#586). The core library does not depend on Micronaut Security. See the Security page.
- HTTP access (#23): a resolver reads the `HttpRequest` of the operation and changes the `MutableHttpResponse` (a header or a cookie reaches the client), as method parameters. Over WebSocket the request is the upgrade request, `Optional<MutableHttpResponse<?>>` is empty, and a plain response parameter is an error of the field with `HTTP_RESPONSE_UNAVAILABLE`. See the HTTP Access page.
- File upload (#47): the module `micronaut-graphql-tools-upload` implements the GraphQL multipart request specification: an `Upload` scalar and a `multipart/form-data` route on the endpoint path. An invalid request is rejected: a `map` path without a `null` placeholder, or an `operations` part without a query (#544). The guide covers decoding on the event loop and CSRF. `micronaut.graphql.tools.upload.enabled` switches it off.
- Standard scalars (#46): the module `micronaut-graphql-tools-scalars` registers the `java.time` scalars, JSON and a selection of extended scalars, so a schema only declares `scalar LocalDate`. Date patterns accept the optional-era forms (#450); the JSON scalar rejects NaN and infinity nested in a value (#449) and a float literal that underflows to zero (#455), keeps integral `Number` types exact (#456) and no longer overflows the stack on a cyclic programmatic variable (#531).
- Observability (#24, #495, BC-38, BC-39, BC-49): every `Instrumentation` bean is installed in the `GraphQL` bean of the library, chained in bean order (BC-38). Metrics and tracing follow the Micronaut conventions (BC-39): `micronaut.metrics.binders.graphql.*` for the metrics and `micronaut.graphql.tools.tracing.*` for the spans, built on the OpenTelemetry `Instrumenter` API, with the field span selection on the field decorator SPI (#483). The module is split by technology (BC-49, #570): `micronaut-graphql-tools-micrometer` and `micronaut-graphql-tools-opentelemetry`, with one `Instrumentation` bean in `graphql-tools` for both. See the Observability page.
- Models and type system (#68, #70, #76, #180): `@GraphQLModels` introspects external and generated model classes, and carries every declared `@Introspected` member (`accessKind`, `includes`, `excludes`) over when it re-annotates a class (#588); it keeps its introspections when another processor re-annotates `@Introspected` (#528) and warns on classes and packages that two annotations name (#589). Union members and interface implementations are derived from `implements` relations and a naming convention (#70) and from the permitted subclasses of a sealed type (#487). Kotlin data classes and default arguments work as models, inputs and parameters (#180).
- Interfaces and markers (#71, #73, #74, #77, #454, #563): an interface type resolver applies to an interface that no field returns, abstract-type ambiguity is detected at startup, and the lookup mode of an interface-mapped type is logged. The resolver marker interfaces `QueryResolver`, `MutationResolver`, `SubscriptionResolver` and `TypeResolver<T>` in the package `io.micronaut.graphql.tools.resolver` (#73, BC-34) fix the root operation type and give the source type as a type argument with no class literal; only the methods that implement a method of a contract interface bind, so a public helper binds nothing and does not trip strict mode. The visitor of `graphql-tools-processor` records the operations, the source type and the contract methods in the annotation metadata of the implementation (refined in #454), and a bean that mixes a root marker with a `TypeResolver` contract binds each method on its own side (#563). The startup and the compile-time checks use the same rules.
- Kotlin and Groovy runtime (#181, #182, #183, #184, #185): Kotlin `Flow` on subscription fields is adapted to a `Publisher` once for each field, collected once for each subscription in the propagated context and cancelled with it; a `Flow` without kotlinx-coroutines-reactive fails with `[flow-without-reactive-coroutines]`. A Kotlin `suspend` resolver binds as an async field with the propagated context visible in the coroutine, and fails with `[suspend-without-coroutines]` without kotlinx-coroutines-core. The support is a bean that exists only when the Kotlin classes are on the classpath, so a Java-only application links no Kotlin type. A Groovy field of `String` may use `GString` as its Java type, Groovy-generated properties bind as getters and input setters, and Groovy 4 `sealed` interfaces work as unions and interfaces. See the Groovy page.
- Compile-time checks (#146, #183, #404, #405, #406, #419, #439, #459, #486, #563, #564, #565): Kotlin nullability is checked against schema nullability (also under kapt, from Kotlin metadata or nullable stub annotations); a Kotlin `internal` resolver method is checked against its mangled JVM name; a package-private resolver method is reported, and an unbound non-public resolver method says to make it private (#438); union member and interface implementation classes that an annotation maps, and FIELD-access models, are checked; `unmapped-input-property` is reported under KSP for settable Kotlin input properties; `Completable` on a non-null field has a rule; the visitor and the startup agree on a raw `CompletionStage` return type and on a schema with no schema definition and no Query type; resolvers exposed by a factory, including Java records, are checked; and the suspend-aware arity is used under kapt. The processor options guide and the Maven sample build cover `looseNullability` and the build-tool snippets (#484, #546).
- Native image (#62, #151, #536, #550, #568): every feature category has a native test in the Java and Kotlin suites, a native-covered case for an unreturned interface resolver, and the HttpTck, protection and http scenarios run natively. Native images are built with shared-arena support, so the security tests log no `Arena.ofShared` error from event-loop threads, and the Kotlin suite runs KSP in full (#566).
- Build and CI (#407, #410, #411, #412, #418, #530, #535, #569): the class loader leak of the corpus test JVM is fixed, the kapt corpus batch compile is isolated per worker, and the Compressed class space use is measured on JDK 27 before and after (#535). `gradle-profiler` scenarios and a compile-time budget measure the cost of the compile-time checks (#418). A guard script checks that every list of modules agrees with `settings.gradle.kts` (#569). The canary failures on JDK 27, graphql-java latest and Kotlin latest are fixed, and dependency downloads are retried.
- Benchmarks (#417, #430, #482, #532, #533, #574): JMH cases measure the execution hop (event loop direct, one hop per request, a hop per field), the per-class binding rules (`BindingRulesBenchmark` on a `ClassElement` fixture) and field decorators. The `invocationOverhead` and `observedInvocationSlope` allocation gates now subscribe to the `Mono`, so they measure the request.

- Resolver marker interfaces (#73, BC-34): `QueryResolver`, `MutationResolver`, `SubscriptionResolver` and `TypeResolver<T>` in the package `io.micronaut.graphql.tools.resolver`. A marker fixes the root operation type (the root type that the schema names for the operation), `TypeResolver<T>` gives the source type as a type argument with no class literal, and only the methods that implement a method of a contract interface bind, so a public helper of an implementation binds nothing and does not trip strict mode. The visitor of `graphql-tools-processor` records the operations, the source type and the contract methods in the annotation metadata of the implementation, and the startup reads them from the bean definition. The reflective read of a class annotation in the registry is removed. The compile-time checks and the startup use the same rules for the markers.
- Kotlin `Flow` on subscription fields (#181): a method of a `Subscription` field can return a `Flow<T>`. The library adapts it to a `Publisher` once for each field at startup, collects it once for each subscription in the propagated context of the operation, and cancels the collection when the subscription is cancelled. A `Flow` on any other field fails the startup. The adapter exists only when kotlinx-coroutines-reactive is on the classpath; binding a `Flow` subscription without it fails the startup with `[flow-without-reactive-coroutines]`.
- Kotlin `suspend` resolvers (#185): a `suspend` function binds as a query, mutation or type resolver method, its continuation is not a parameter, and the field is an async field. The support is a bean of the library that exists only when the Kotlin and kotlinx-coroutines classes are on the classpath, so a Java-only application and its native image link no Kotlin type. The propagated context is visible inside the coroutine, an exception becomes an error of the field, and cancelling the field cancels the coroutine. Binding a `suspend` function without kotlinx-coroutines-core fails the startup with `[suspend-without-coroutines]`.
- Default error handling (#32, BC-37): the message of an unhandled exception is hidden (`Internal server error`, code `INTERNAL_ERROR`), `GraphQLExceptionMapper` beans map an exception type to an error with a message and extensions, by order, matching the real exception of a failed `CompletionStage`; `GraphQLErrorsCustomizer` changes the final list of errors; a `ConstraintViolationException` becomes one error for each violation with its argument path. `micronaut.graphql.tools.errors.details` shows the message in development, `micronaut.graphql.tools.errors.stack-traces` adds the stack trace to the log entry. See the Errors page.
- Groovy runtime (#182): a field of `String` may declare Groovy's `GString` as its Java type, as a result, as the element of a `CompletionStage`, or as a property getter. The library adds no conversion step: graphql-java's `String` scalar serializes it with `toString()`. Properties that Groovy generates bind as getters and as input setters, and Groovy 4 `sealed` interfaces work as unions and interfaces. See the Groovy page.

## Other behaviour changes

- By default every operation runs on the `blocking` executor, so a blocking resolver no longer stalls the server (BC-35). With `micronaut.graphql.tools.execution.executor: none` there is no hop and the operation runs on the receiving thread, as before. The `GraphQLExecutionInputCustomizer` is the one step that runs on the subscribing thread.
- A resolver class annotated only with `@GraphQLRootResolver` or `@GraphQLTypeResolver` is no longer a bean (BC-34), so add a scope annotation such as `@Singleton`.
- A WebSocket operation has the upgrade request as its request. A plain `MutableHttpResponse` parameter over WebSocket is an error of the field with `HTTP_RESPONSE_UNAVAILABLE`.
- A multipart request that is not valid is rejected with an error before the invocation runs.

## Known limitations

- A resolver that is already running is not interrupted by a timeout or a client disconnect; only the continuation of its async fields and later async fields are aborted.
- `protection.introspection: false` hides the schema fields from clients; it replaces a field visibility that the application set on the schema, and it is not an access control.
- An expression-form `@Secured` value is rejected at startup; the security module decides on roles and the authentication state only.
