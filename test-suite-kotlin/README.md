# test-suite-kotlin

Gradle project `:test-suite-kotlin`, folder `test-suite-kotlin/`. Not published.

## Purpose

The example application in Kotlin (Kotlin 2.1.21 with KSP2, Java and Kotlin target 21), and the test suite that runs it.
It uses `micronaut-graphql-tools` with the Micronaut KSP processor. It has JUnit tests over HTTP and the native image
tests. The guide's code snippets include the Kotlin version of each example from this module.

## Responsibility

- `src/main/kotlin/example`: the application: resolvers, data classes and the `GraphQLFactory` bean. Its schema is
  `src/main/resources/schema.graphqls`, a copy of the Java suite's schema (checked by `checkSuiteSchemaParity` in
  `test-suite-java`).
- `src/test/kotlin/example`: JUnit tests by feature: `discovery`, `scope`, and `GraphQLSmokeTest`. `tck` holds the fixtures
  of the execution-behaviour scenarios, and `GraphQLToolsTckTest` runs them.
- `src/serdeTest/kotlin/example/client`: the client examples of the guide, the Kotlin version of `example.client` in `test-suite-java`
  (`ExampleClient` and `ServiceClient` with `suspend` operations and data classes, `LowLevelClientTest`, `DeclarativeClientTest` and
  `ServiceClientTest`), on the Micronaut Serialization stack: the client needs Serde, and `micronaut-serde-jackson` makes its `JsonMapper` win
  over Jackson databind, so the two stacks cannot share a classpath and `test` keeps the Jackson databind stack. KSP checks the operation
  documents of `src/serdeTest/graphql/client/server` against the schema of the application (`client.dirs`, the client schema `server`).
  `checkClientExampleParity` in `test-suite-java` compares the class names, the tags and the documents with the Java suite.
- The schema index of the discovery test is generated by the task `graphqlSchemaIndex`, because a native image cannot list
  a classpath directory.

Not in this module: the library (`graphql-tools`), the shared scenarios (`test-suite-tck`) and the compile-time checks
(`graphql-tools-processor`, which this suite does not use).

## Who uses it

Maintainers and CI. Application developers can read it as an example of a Kotlin application.

## Public and internal

Nothing here is a library API. Do not import from `example.*` in application code.

## Relation to other modules

- Depends on `micronaut-graphql-tools` (`implementation`) and `test-suite-tck` (`testImplementation`).
- Uses the Micronaut Kotlin runtime and KSP (`micronaut-inject-kotlin`). It does not depend on `test-suite-java`.

## Build and test

Run from the repository root. JDK 21 or 25 (native tests need Oracle GraalVM 25; see `mise.toml`).

```
./gradlew :test-suite-kotlin:test
./gradlew :test-suite-kotlin:test --tests 'example.tck.*'
./gradlew :test-suite-kotlin:serdeTest
./gradlew :test-suite-kotlin:nativeTest :test-suite-kotlin:nativeSerdeTest --no-parallel
```

- `test` runs the JUnit tests on the JVM (Jackson databind stack); `serdeTest` runs the client examples (Micronaut Serialization stack). Both are part of `check`.
- `nativeTest` and `nativeSerdeTest` build a native image and run the tests of their source set in it. Each takes about 5 to 7 minutes and
  5 GB of memory. Run them one after another and after the other native tests, not in parallel with them.
- Add `-PgraphqlJavaLeg=floor|ceiling` to run on another graphql-java leg.

The full list of the commands CI runs is in `CONTRIBUTING.md` ("Running Tests").
